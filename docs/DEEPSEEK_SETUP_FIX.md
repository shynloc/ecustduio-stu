# DeepSeek 调用授权引导修复

日期：2026-11-08。

问题：密钥单独保存，调用授权需要再次保存全局设置。用户即使已勾选授权，测试仍读取旧配置，报错没有指出具体操作位置。

修复：增加独立「调用授权」区域，展示待开启、更改未保存、已开启状态；未满足条件时禁用测试并给出下一步。授权勾选后可直接「保存并测试连接」。预算参数折叠在高级设置中，授权与主操作保持相邻。已输入但未保存的新密钥也会阻止误测旧凭据。

新增 PATCH /api/settings/deepseek，只接受模型、调用授权与预算字段，使用revision冲突保护，不提交监测或推送设置。部分保存及后台刷新会保留页面上其他未提交的设置。连接测试失败及空响应不会显示成功；服务端授权错误包含明确的设置位置与按钮名称。

验证：类型检查和生产构建通过；28项后端回归通过；专门的浏览器测试覆盖无密钥、未授权、授权未保存、先保存后测试、保存失败零测试请求、其他设置不被提交且草稿保留、刷新持久化、新密钥未保存、模型失败/空结果、关闭授权、390px手机布局。模型返回由浏览器测试替身拦截，没有使用生产密钥或调用真实DeepSeek。证据：test-results/deepseek-setup/result.json。

运行版本已更新。生产设置、凭据配置状态与数据计数在重启前后保持一致，见production-verification.json。用户刷新设置页面即可使用新流程。
