# 0.8.3 凭据保存修复

用户现场为Mac本机127.0.0.1:37891。仅收到通用INTERNAL_ERROR，未取得Mac原生日志；未将钥匙串锁定、授权取消或文件权限中的任何一种宣称为该机器的已确认根因。

变更：
- Mac钥匙串调用拆出可测试的客户端。凭据仍经stdin提交，不进argv或shell历史，保存后精确读取比对。security退出成功时允许附带诊断输出；失败按安全的固定消息分类，不向前端转发原始stderr。
- 捕获stdin EPIPE、工具启动失败和授权超时，避免未处理异常。拒绝超长交互命令及控制字符。串行保存避免配置标记被并发覆盖；保留原service/account命名，兼容已有钥匙串项。
- 凭据配置文件错误以提示呈现，不使state整体失败；没有删除或重建原配置。
- 设置卡片显示等待、成功及具体错误，禁止重复提交和隐式表单跳转。保存失败保留密码输入，不跳转。
- 管理员凭据诊断使用临时测试项，写入、读取后删除，不使用真实Key或DeepSeek额度。Mac增加终端隐藏输入与本机诊断入口。
- HTML导航发生服务异常时显示恢复页面，API继续返回结构化错误；内部分支和密钥不会显示在错误页面。

不改变Windows DPAPI、Mac钥匙串身份、数据库迁移或更新签名机制。原有数据按现有升级器保留。

验证记录位于发布验收文件：包含模拟Mac钥匙串单元与API测试、真实浏览器错误/重试检查、Windows凭据读写及升级数据保留。未进行Mac实机钥匙串验收。
