# EcuStudio 教创工作台：OCR 接入与验收

验收日期：2026-11-08。当前版本已构建、重启，并在运行中的工作台复核。

## 使用方法

1. 进入「政策情报 → 添加资料 → 上传文件」，选择 PNG、JPEG、WebP 图片或 PDF。
2. 图片、扫描 PDF 自动进入本机 OCR；混合 PDF 按页使用文本层或 OCR。界面显示任务进度、页数和错误；也可强制重新识别全部页面。
3. 对照原文件检查「提取预览」，尤其是日期、数字和段落顺序。可以直接修改预览，再填写资料来源、范围并导入。
4. 在资料详情运行 AI 研究，提取候选事实；按现有流程核验事实、创建项目、生成母稿和不同形式的内容。
5. 关闭导入窗口后，识别任务仍可在「任务与自动化」查看。已完成的 OCR 任务可点击「校正并导入识别结果」继续。

识别后保留原始文件链接、逐页文字、原始 OCR 结果、来源文件哈希，以及是否人工校正的标记。资料段落继续携带页码，进入现有事实引用和母稿依赖链。OCR 不会自动将事实标为已核实。

## 实现

- 本地 Windows.Media.Ocr 引擎；本机已验证 zh-Hans-CN 语言包。OCR 本身不向云端上传文件，不需要额外服务凭证。后续 DeepSeek 研究和生成仍遵循工作台现有调用授权。
- PDF 使用 pdfjs 解析，扫描页渲染成位图后识别；图片统一解码、缩放并以白底处理。使用 `@napi-rs/canvas` 和 `image-size`，运行时不依赖 Python。
- OCR 使用现有持久任务队列，支持进度、取消、失败重试和结果恢复。导入接口验证识别任务与原始文件匹配，随后复用资料快照、事实、母稿和内容生成流程。
- 原始识别结果保存为 JSON 资产，包含行、词和位置。仅清理汉字之间的多余空格，不自动合并或推断数字；引擎未提供置信度，因此记录为 null。
- 工作台的日常状态轮询不携带全部 OCR 文字和坐标，避免大文档造成任务列表膨胀。

主要实现：`server/ocr.ts`、`scripts/windows-ocr.ps1`、`server/app.ts`、`server/tasks.ts`、`server/domain.ts`、`web/main.tsx`。

Microsoft 参考：[OcrEngine](https://learn.microsoft.com/en-us/uwp/api/windows.media.ocr.ocrengine?view=winrt-26100)、[RecognizeAsync](https://learn.microsoft.com/en-us/uwp/api/windows.media.ocr.ocrengine.recognizeasync?view=winrt-26100)。

## 真实 DeepSeek 完整流程

在运行中的工作台，使用已保存的 DeepSeek 凭证实际执行：

**两页扫描 PDF → 本机 OCR → 对照样例校正数字间距 → 导入 → AI 提取 3 条候选事实 → 生成母稿 → 生成 60 秒口播 → 导出 DOCX。**

## 限制与后续使用

- 单次 OCR 最多 30 页；普通上传最多 50MB；单张图片最多 4000 万像素。加密 PDF 请先解密。
- 本机 OCR 需要 Windows 和可用的识别语言包；不支持以相同方式在 macOS/Linux 运行。设置页显示实际探测能力。
- 日期、数字、专名和阅读顺序可能误识别，应对照原件校正；复杂表格、印章遮挡、手写、旋转或模糊图片需要人工复核。
- OCR 完成不代表事实真实或可发布，现有事实核验和内容审核门槛继续生效。
- 本次支持上传文件识别；网址导入中的扫描 PDF 不自动调用这条上传 OCR 流程，可先下载后上传。

复现命令：`npm run check`、`npm run build`、`npm test`、`npx tsx tests/ocr.e2e.ts`、`npx tsx tests/deepseek-settings.e2e.ts`、`npm run test:e2e`。真实模型验收脚本为 `scripts/live-ocr-flow.ts`，重复执行会产生真实调用和新的验收资料。
