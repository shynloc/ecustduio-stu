## 1. 接手约定与交付定义

本计划以用户 2026-11-19 的反馈为最新产品要求。用户要求所有正文编辑器统一图标化并默认所见即所得，首页具有 3D 动效，知识和成果统一管理，Agent 对话具备完整制作能力，项目明显简化。过去“Markdown 编辑+单独预览即可”的做法不再满足验收。

代码改动以完整用户路径为交付单位。每个任务同时完成页面状态、服务端校验、失败恢复和必要验收；不能只新增组件而保留旧入口继续暴露相同问题。

开工先检查当前分支、未提交变更和远端，复用当前工作副本。迁移编号、最新模型能力与现有组件以开工时源码为准；不要用本文件的基线覆盖 Mac 后续改动。开发使用 `.local-data` 或 `test-results` 的隔离数据，禁止重置生产目录。

## 3. 架构决定

### ADR-01：统一文档内核，不再按页面维护不同编辑体验

复用已有 TipTap、`note_documents`、`note_history` 和 Markdown 转换设施。建立统一 RichDocument 层：schema version、document JSON、原始格式片段、来源映射、revision。已有原始资料与文件保持不变；编辑文档与原件分离。

编辑器格式按钮全部使用 `EditorIconButton` 同类组件；移除“默认文字按钮，某页面特例开启图标”的分叉。渲染器同源使用文档 schema，仍保留安全 Markdown 渲染兼容。表格、公式、脚注、图片及引用必须覆盖读写回环；无法编辑的块保真显示，提供块级高级编辑，不整篇退回源码。

收益：一次修复覆盖所有页面，统一保存、快捷键和中文输入体验。成本：需要完整序列化兼容测试与旧内容惰性转换；不能简单替换成 `contentEditable` 或强制把所有原文重新序列化。

### ADR-02：共用集合管理框架，保留不同内容的行为

建立 `CollectionBrowser`、`FolderTree`、`TagFilter`、`BulkActionBar`、`ViewSwitcher` 和实体适配器。知识、原始资料、成果的搜索和选择行为一致；对话使用同一分类基础与独立会话列表。

管理框架不承包所有业务：成果保留格式预览、版本与下载，知识保留正文编辑和引用，原始资料保留原件。不要用一份巨大条件组件混合所有权限和 API。

### ADR-03：共用任务事件和模型适配器

复用现有 `jobs/events`、Worker、检查点和幂等键，不增加第二套后台队列。扩展可恢复事件类型：`stage`、`progress`、`text.delta`、`artifact.ready`、`usage`、`warning`、`completed`、`failed`、`cancelled`。用户状态文字由前端映射，诊断数据保留在受权详情中。

流式处理写在服务端 provider adapter：Chat Completions、Responses 分别解析；工具参数增量、工具结果、回答增量、结束原因和用量归一化。按官方要求保留工具循环需要的 `reasoning_content`，但不将内部推理作为用户等待状态展示。[思考与工具调用协议](https://api-docs.deepseek.com/guides/thinking_mode/)

服务端持久记录最终消息与可重放检查点；文本增量适度批量落库，不能每个 token 单独开事务。用户重连恢复事件，不重新调用模型。停止操作贯通前端、Worker、网络 AbortSignal 和子任务；已经完成的作品仍保留。

### ADR-04：统一上下文与作品动作登记

复用 `web/context.ts` 与现有冻结材料机制，新增统一 `ContextPicker`、`ComposerTools`、`MessageActions`、`ActionRegistry`。入口只传来源 ID、版本、用户意图和需要的设置；服务端重新校验访问权限并读取内容，不相信客户端提交的“已授权正文”。

工具描述包含输入类型、输出类型、权限、依赖配置、进度、取消方式和副作用。接入现有 HTML Creator Studio、GIF Factory、配音、文档导出、公众号及视频工具，不重写制作引擎。来源与消息 ID 贯穿任务、版本、作品和预览。

### ADR-05：持续对话采用预算管理，不靠固定消息数截断

完整历史持久保存；模型输入使用近期消息、可回溯摘要、选中资料和按需检索。每份摘要记录覆盖消息区间和依据版本，用户改历史、换材料时使相关摘要失效。

容量依据实际模型及端点能力，预留输出、工具结果与协议开销。预估与接口返回用量分开；未知能力采用明确保守预留和可见提示，不显示虚构精确百分比。官方模型信息作为能力刷新依据，但字段缺失时不得猜成已知。[模型查询文档](https://api-docs.deepseek.com/api/list-models/)

## 4. 数据与 API 设计清单

以下为拟新增/调整契约，不代表当前接口已经存在。命名在实现时可随现有路由约定统一，但语义和验收不能省略。

### 4.1 追加数据结构

| 数据 | 设计重点 |
| --- | --- |
| 分类目录与成员关系 | owner/scope、实体类型、parent、排序；父子关系禁止循环；同名目录按用户隔离；知识与对话不能意外混合成员 |
| 标签关系与管理 | 保留现有标签，规范化 ID；按用户/可见范围合并，防止跨用户重命名；可检索、可增删而非整组替换 |
| 用户视图偏好 | 列表/卡片、侧栏、排序、列宽；按账号存储，不同用户不共享浏览器缓存身份 |
| 对话元数据 | folder、pinned、archived、deleted；不重建已有 conversations/messages ID |
| 输入草稿与阅读位置 | 用户+对话/文档+revision，冲突检查；退出登录清理不适合保留的本地内容 |
| 文档 schema 与来源映射 | 扩展已有 note_documents；稳定 block ID、页码、原段落 ID、原始片段、格式版本；文件原件不改写 |
| 对话摘要与流式检查点 | 摘要覆盖范围/版本、run/message、事件 seq、终态；复用已有 events，避免重复保存相同工具结果 |
| 成果分类与版本关联 | 分类为元数据；产物文件和历史版本不可静默覆盖；关联 source revision、project、conversation |

当前迁移到 `009_project_html_films.sql`。新增编号在实施前检查远端，追加 SQL 并注册 `server/db.ts:migrateExtensions`。已有 `note_categories.folder` 是字符串，迁移时按 owner 保留字面名称；不能凭一个斜杠自动拆层级，也不能将不同用户同名文件夹合并。旧接口需在过渡期正确读取新分类。

所有新增业务表加入 `deployment/upgrade.mjs` 的保留清单；新 schema 的回滚需匹配升级前数据库备份，不能只换回旧二进制后继续写新库。保留 DeepSeek、语音、公众号凭据与原更新签名信任链。

### 4.2 查询与批量契约

- 列表接口支持 `q/folder/tags/type/state/date/sort/cursor`；响应含条目、下一页、可见总数及分类计数。先应用账号权限，再搜索、聚合、分页。
- 文件夹计数默认包含子目录，标签数量按匹配内容去重，均排除回收站；筛选结果数和侧栏总数采用不同明确标签，不混用。
- 批量操作支持显式 IDs 或服务端冻结的筛选快照；展示实际数量。按条目重新鉴权，返回成功/失败明细；不要静默跳过权限问题。
- 标签采用 `add/remove`；移动采用目标目录；删除采用 soft delete。批量撤销需记录旧值/目标 revision，冲突时不覆盖后来编辑。
- 对话和知识支持服务端全文搜索与分页，不受当前 LIMIT 200/1000 的 UI 加载数量限制。首次可用 SQLite FTS5 配合现有检索，索引回填可恢复；不强制新增外部数据库服务。

### 4.3 任务与上下文契约

- 提交动作返回固定 jobId 和幂等结果；ContextRef 携带 kind/id/revision，服务端冻结可见材料。上下文已变更时允许明确刷新，不能悄悄替换历史依据。
- 事件订阅建议 `GET /api/jobs/:id/stream?after=<seq>`，基于登录会话、ACL、单调 seq 和断线重放；保留轮询回退。具体路由与已有任务接口合并。
- 无已知工作量时 progress 不含 percentage；有已知总量时提供 completed/total/unit。估算剩余时间只有足够样本时显示并标为估算。
- 对话工具请求保持结构化且可校验。未登录、业务员越权、他人私有知识、受限网址/文件、未配置外部服务均在执行前返回可理解原因。
- Provider 中途失败不能自动以非流式重发一遍付费请求；保留已收到内容，按可安全重试状态恢复。SSE keepalive 不算正文，结束错误与正常完成分开。[官方 Web 工具流式说明](https://api-docs.deepseek.com/guides/web_tools/)

## 6. 三个专项功能的审计矩阵

| 专项 | 实际输入/故障 | 正确结果 |
| --- | --- | --- |
| 识别 | 纯文本 PDF、扫描 PDF、混排、旋转页、多栏、表格、带数字信息图 | 对照原页；保留顺序、数字/单位/标题、页码；不能用文件名生成内容 |
| 识别 | 超限长 PDF、大图、单页失败、取消、断网 | 自动分组、可见总页数、已完成保留、只重试缺失段；截断不能成功入库 |
| 转写 | 长录音、静音段、坏音频、分段服务失败 | 可定位时间，明确失败段，成功段复用；不声称静音含不存在的文字 |
| 识别配置 | 无连接、权限不够、配额不足 | 同页可理解错误和设置入口；不跳到 JSON 页面 |
| 更新 | 原文正文/数字变化、只有格式变化、资料被撤回 | 区分有效变化，引用仍定位，关联私有内容不越权 |
| 更新 | AI 分析错误引用、重复检查、接受部分修改 | 拒绝虚构引用，重复不建重复影响，旧版本保持可用 |
| 日报 | 无新增、部分来源失败、全失败、首次无配置 | 四种状态不同；无新增不能遮掩失败 |
| 日报 | 时区、工作日、补跑、并发手动/自动、重启 | 计划清楚、去重、不补造未运行历史；恢复行为符合产品说明 |
| 日报 | 业务员/创作者/管理员、失效来源链接 | 可见范围一致，配置仅授权用户可改，用户可到原来源核对 |

## 8. 风险、处理与交付物

| 风险 | 具体处理 |
| --- | --- |
| 富文本转换损坏旧内容 | 原件不动，带 schema 的版本保存，复杂片段保真；读写回环验收 |

| 大量选择导致上下文爆满 | 预算预留、摘要+检索、来源清单与实际使用说明 |
