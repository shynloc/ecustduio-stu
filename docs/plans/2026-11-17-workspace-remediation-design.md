# EcuStudio 教创工作台：问题修复与产品整改方案

日期：2026-11-17 ｜ 基线：当前源码 0.8.3，用户截图显示 0.8.2 ｜ 状态：方案，尚未实施

## 1. 本次结论

工作台需要围绕 **输入 → 处理 → 输出** 重新组织，并让所有入口共用同一份资料、同一套任务执行器和同一条来源链。优先解决“拿到错误内容仍可继续创作”与“任务无法执行”，再解决阅读、组织和制作体验。

推荐在现有系统上逐步整改。保留账号、资料、笔记、项目、主题、DeepSeek 凭据和升级机制；复用已有事实提取、母稿、导出、HCS、GIF Factory 与配音渲染能力。导航重排必须伴随数据与流程打通。

本轮查阅了实际代码、既有产品文档、两张截图及 DeepSeek 当前官方接口文档。没有学生 Mac 的原 PDF、失败链接、任务日志或当时配置；因此区分“已确认代码行为”“明确的接口兼容缺陷”和“仍需原样本定位的原因”。本轮没有调用收费模型，没有修改运行程序、业务数据或更新源。

### 方案取舍

| 路线 | 优点 | 问题 | 决策 |
|---|---|---|---|
| 只修按钮、错误提示和导航 | 见效快 | 多套资料与生成流程仍然分散，错误继续向后传递 | 只用于第一批紧急修复 |
| 共用资料处理、知识库与创作任务，逐步改造入口 | 可复用已有功能；可以分批验收、平滑升级 | 需要清晰的兼容层与数据迁移 | **采用** |
| 重写整个工作台 | 可重新设计全部结构 | 周期长、迁移风险高，已有成果链需重做 | 本次不采用 |

## 2. 问题清单与证据

P0：错误内容扩散或核心任务阻断；P1：常用流程缺失、明显失效；P2：体验与能力完善。优先级不是归责结论。

| 编号 | 用户问题 | 已确认的现状 | 判断与优先级 |
|---|---|---|---|
| F01 | 公众号公开链接导入失败 | 网址导入仅通用 HTTP 获取和 Cheerio 文本抽取；没有公众号正文/懒加载图片适配，也没有验证页识别与分级恢复 | **P1**。具体链接可能涉及验证、过期、动态加载或正文选择器；没有原链接，不能定为单一原因 |
| F02 | 网页/PDF 图文混排只读文字 | HTML 最终调用 `.text()`；DOCX 使用 `extractRawText`；PDF 只提文本层，本机 OCR 遇到 ≥20 个非空白字符就跳过整页图像识别 | **P1**，代码已确认。带少量文字和大量图表的页面会漏读；云端已有图文模式，但各入口没有统一自动选择 |
| F03 | 一句话任务管家有无材料都报错 | `structuredTask` 同时使用指定 `read_skill` 的 `tool_choice` 与全局思考设置；全部 HTTP 400 都改成同一条提示 | **P0**。开启思考时该请求组合违反官方约束；截图是否由它触发，仍需当次配置/错误详情确认 |
| F04 | 识别结果和笔记直接显示 Markdown | 媒体结果与笔记主区默认是 textarea；AI 探索消息已经使用 `Answer` 渲染，但保存成笔记后又进入源码编辑 | **P1**。不是完全没有富文本能力，是显示与编辑模式不一致 |
| F05 | 创作步骤多，模板需要手填 | 已有 `runProduction` 自动事实→母稿→内容→导出，也有任务管家和项目内手动编辑路径；入口、状态和参数未统一 | **P1**。复用自动引擎、统一默认路径，避免另建第四套生成流程 |
| F06 | 教学 PDF 结果出现无人机 | 截图为“文档解析”AI 整理结果；代码有本地资产哈希校验和任务绑定，但接受非空模型回答即成功，缺乏逐页对应及内容一致性校验 | **P0**。可能是文件本身/文本层/远端解析/模型输出/前端状态的问题，尚不能证明串文件或某一家接口幻觉 |
| F07 | 大文件远端失败后要求手动拆分 | 云端 OCR 整文件上传，一页截断即整任务失败；本地 OCR 限制30页；媒体上传限制50MB；音频已有分段检查点，PDF 没有 | **P1**。补齐自动分片、逐片记录、部分成功与失败页续跑 |
| F08 | 右侧输出格式拥挤 | 制作区固定320px侧栏，格式选择为 flex-wrap 标签；缺少独立格式项宽度与布局规则 | **P1**。需结合原浏览器宽度、缩放与样式计算复现；不能仅凭代码断定唯一 CSS 冲突 |
| R01 | 按输入、处理、输出重组 | 现有导航以各次新增功能命名，入口平铺；笔记、政策资料、媒体结果分开保存和转换 | **产品主线**。知识库统一组织与引用，原文件/摘录/分析/成果保持区别 |

### 额外发现：无关资料被兜底选入任务

`freezePlan` 在不选材料时取最新150份资料，`runPlan` 提示词要求“没有相关材料就选最接近的资料”，而计划结构强制至少一份材料。这会把“找不到证据”错误变成“拿不相关证据继续做”。必须删除该兜底。此处与 PDF 无人机结果尚无直接因果证据，不能混为一个已确认故障。

## 3. 紧急修复方案

### 3.1 任务管家：程序保证请求兼容，资料不足有可用状态

- 统一请求构造器，覆盖任务管家、来源预审、视觉设计等共用 `structuredTask` 的调用者。
- 必须使用的技能由宿主预先装载允许范围内的规范，记录技能版本/哈希；作为系统上下文传入，不伪造模型工具调用历史。后续工具保持 `auto`，保留用户选择的思考强度。
- 如短期兼容必须强制工具，仅该轮明确关闭思考；禁止静默全局关掉思考。最终 JSON 输出可单独收敛，校验必填结构后才保存。
- 保留现有 `reasoning_content` 等协议历史回传；不要向普通用户展示模型思考原文。
- HTTP 400 区分模型不支持、参数冲突、上下文超限、文件引用异常。记录脱敏的错误码、param、requestId、阶段与参数摘要；不要存完整密钥或文件内容。
- 用户不选材料时，明确进入“从我的知识库查找”；只检索其权限内资料。允许显式选择“联网补充”，不在背后上传全部知识库。
- 无相关资料时返回“缺少资料”的可编辑计划：提供粘贴文本、上传、选笔记、联网补充入口。一般教学/创意任务可在用户明确选择后制作无来源提纲，标为创意草稿；政策事实任务不得用无关材料填补。
- 失败停在当前步骤，保留任务要求、材料、已完成结果；可重试失败步骤和调整后新建版本。

官方依据：思考模式不支持 `required` 或强制指定具体工具；已有工具历史须按协议回传。[DeepSeek Chat Completions](https://api-docs.deepseek.com/zh-cn/api/create-chat-completion/) · [思考模式](https://api-docs.deepseek.com/zh-cn/guides/thinking_mode/)

### 3.2 PDF 内容错位：先建立可靠原文，再允许整理

默认流程改为：**确认原文件 → 按页提取/识别 → 原文对照 → 整理摘要 → 存笔记/用于创作**。普通用户看到“识别原文”和“整理内容”两个明确结果，后者不能覆盖前者。

排查顺序：

1. 固定 sourceAssetId、SHA-256、文件大小、页数、任务ID；对照上传时预览和处理时实际字节。
2. 打开 PDF 第1页、中间页、末页及异常页，比较渲染画面与隐藏文本层。文件名不代表正文，也不用于强迫模型产生同主题内容。
3. 记录每次远端 file_id、purpose、字节数、模型、片段页码；检查元信息是否对应，不将文件列表中的“最新文件”当本任务文件。
4. 核查前端切换历史任务/重新上传时是否清空上次结果，过期响应是否仍能覆盖新任务；缓存键包含所有者、内容哈希、解析方式、引擎版本和参数。
5. 用独立逐页 OCR/渲染结果与文件问答结果比较。关键实体、数字、引文不存在，或结果明显跑题，标为“解析结果疑似不一致”，阻止直接作为原文证据流入事实提取。

限制说明：相似度与第二次模型判断只是异常检测，不能证明内容真实。以原文件预览、页码、可定位原文和用户校正为依据；任何“不一致”不自动改写为与文件名相符的文本。

异常内容可以存为带醒目标记的待复核笔记，不能自动成为已核验事实。重新识别产生新版本，保留旧结果，列出受影响笔记、事实、稿件及导出文件，避免静默覆盖历史成果。

### 3.3 图文混排：文本、图片、表格一起进入资料模型

- 网页保留段落、标题、列表、表格、图片顺序；处理 `src`、`data-src`、`srcset` 和相对地址，记录来源URL及抓取时间。删除页眉广告时保留正文配图。
- PDF 同时检查文本层、图片区域和页面渲染；不能因有文字就认定无需识图。矢量图表也要由页面渲染检测，不能只数嵌入图片。
- 默认“智能图文识别”：正文提取+图中文字 OCR+必要图表理解。文字识别与图表解释分开保存；重复文字按位置与文本去重，保留原坐标。
- 图表保存标题、轴/单位、图例、可读数据、结论及证据区域。仅视觉估算的数字必须标为估读；无法读清就保留原图、提示局部放大重识别。
- 已授权云端处理时按文档结构选择 `rich_layout_recognition`；不能假定云端会裁出每张图，关键图表缺失时走整页/区域识别。本机模式保留文字OCR，不能冒称已完成语义看图。
- 单一资料页展示“原文、结构化内容、图表、整理笔记”，可双向定位。用户无需先判断该点“文档解析”还是“OCR”。

官方说明确认文字模式不把文档图像交给模型，图文模式也不保证裁出每一张图。[DeepSeek 文件解析](https://api-docs.deepseek.com/zh-cn/guides/document_parsing/)

### 3.4 公众号与复杂链接：分级获取，失败可继续

1. 通用 HTTP 抓取 + 公众号正文适配（例如 `#js_content`）、作者/标题/时间、正文图表。
2. 识别“验证/访问受限/链接失效/正文为空”，不能把提示页当成功文章存入知识库。
3. 对允许公开抓取的动态页面使用隔离浏览器读取渲染正文；所有主请求、子资源、重定向继续限制公开地址，并限制时间与资源量。
4. 已开启联网能力时可调用 DeepSeek 阅读链接作为补充，保留获取方法；无法获得全文时不能把搜索摘要标成原文。官方提供 Fetch，但不保证所有公众号可访问。[DeepSeek 网页搜索与抓取](https://api-docs.deepseek.com/zh-cn/guides/search/)
5. 若确需登录/验证，给出“打开原文”“粘贴正文”“导入保存的PDF/HTML/截图”，进入同一处理管线。浏览器能打开不代表服务器可以匿名抓取，不承诺绕过平台限制。

### 3.5 大 PDF：自动分片与按页恢复

先本地预检页数、加密、字节数、图像分辨率；随后按“页数+字节预算”打包小批次。初始建议每片10页、20MiB以内，属于工作台调度参数，可配置并根据超时缩小，不是官方接口上限。

- 超过当前上传50MB的文件要在进入模型前就能接收：大文件改为流式落盘、可恢复上传与磁盘配额控制，不能只修云端拆分按钮。大文件不能整份反复复制到内存。
- 每片保留 originalPageStart/End 与哈希；同一页大于预算时优先渲染为高质量图并分区，保留重叠边界和坐标，避免丢掉表头。
- 413/504/识别超时：拆小失败片；429：按提示退避；401/402/密码保护/格式损坏：停止该策略并给出对应操作，不反复拆分重试。
- OCR 某页 `finish_reason=length`：仅对该页细分重试。完整页继续保留；总状态为“部分完成”，不能报告全文成功。
- 检查点持久化到片级，崩溃/刷新后继续；先按原页序合并，再分块整理。摘要引用原页码，不能把分片第1页误作原文第1页。
- 取消停止后续发送；已提交远端工作可能继续并计费，界面区分“本地已取消”与“远端结果未知”。限制总片数、并发、重试次数和用量，不无限重传。
- 界面显示“已完成32/48页，2页待重试”，并展示识别覆盖率、缺页与原文件。

截至本次核对，官方 OCR 支持单请求100MiB/1000页，但有上传和总处理时限；大小合法仍可能超时。自动拆分必须同时面向速度、上下文和恢复能力。[DeepSeek OCR](https://api-docs.deepseek.com/zh-cn/guides/ocr/)

### 3.6 富文本与格式选择

默认显示排版后的正文：标题、列表、表格、图片、引用、链接。阅读是默认态；编辑进入带工具栏的富文本编辑器；“查看 Markdown”保留在高级菜单。识别原文、整理稿、创作笔记和AI探索使用统一阅读组件。

旧 Markdown 先无损保留，可即时渲染；编辑保存时再生成有 schemaVersion 的结构化文档。代码块、公式、表格、引用与不支持的块不得静默删除；必须保留原文块或提示。支持中文输入法、撤销、粘贴清洗、自动保存、修订冲突提示和图片资产权限。复制默认富文本，纯文本/Markdown是显式选项。原始 OCR 的内部坐标标记留在证据数据，不暴露为正文代码。

输出格式改为可点击的卡片/网格，说明用途，例如“PPTX · 可编辑演示”“PDF · 阅读/打印”。侧栏不足时单列，窄屏移到主流程下方；格式名称不挤压成多行碎片，复选框大小固定，选择状态可见。书院仍为默认主题，曜石保持可用。

## 4. 产品结构：输入 → 处理 → 输出

首页保留“继续上次任务、待处理资料、待复核内容、最近成果”。顶层三组面向普通用户，账号、权限、模型与更新放到底部管理区。不要将任务阶段变成用户必须逐页点击的向导。

| 分区 | 页面 | 用户目的 | 原入口如何迁移 |
|---|---|---|---|
| 输入 | 收集资料 | 粘贴网址/文字、上传文档/图片/录音；自动识别、排版、存入收件箱 | 政策情报的手动导入、素材导入和媒体上传汇合 |
| 输入 | AI探索 | 对话；本地、联网、混合检索；回答可保存为笔记 | 保留 AI探索，增加来源筛选与引用预览 |
| 输入 | 政策情报 | 专业订阅视图，查看监测来源与新文章，区分官方原文/转载/待核验 | 保留现有业务价值，不再承担所有资料的唯一入口 |
| 处理 | 知识库 | 阅读、写作、文件夹、标签、用途分类、搜索、批量整理 | 创作笔记为可编辑内容；原材料与处理结果统一可检索 |
| 处理 | 研读与核验 | 原文对照、事实提取、图表校正、政策变化与引用影响 | 合并可见操作，复用政策影响追踪、来源预审 |
| 处理 | 文档与语音 | 查看识别任务、文件转换、转写校正、文字配音 | 文件与语音更名并与收集入口共用任务；无须再次上传 |
| 输出 | 创作中心 | 选资料/知识库+说目标，生成正文、PPT、网页、图卡、音视频 | 任务管家、选题、模板启动与项目制作收敛为同一工作区 |
| 输出 | 自动任务与日报 | 定时采集→入库→研读→日报/成果；查看执行与失败情况 | 监测计划和成果日报在此配置，输入区展示收集结果 |
| 输出 | 公众号编辑器 | 将文章、图片、引用排版为公众号稿，预览和导出 | 在现有公众号内容类型与HTML出口上增量建设 |
| 输出 | 成果库 | 预览、下载、版本比较、来源状态、再次编辑、整包导出 | 成果与日报拆出统一成果视图 |
| 管理 | 设置 / 账号管理 | 主题、DeepSeek、存储、更新与角色权限 | 角色权限不因导航改动而扩大 |

同一对象只有一份主记录。输入阶段产生的文件保存在知识库中，文档与语音是针对它的处理操作；自动任务是编排入口，政策情报是结果视图，不能分别复制一套数据。

### 移动端

主导航使用“首页、输入、知识库、创作、更多”，对应上述三段结构。来源对照从桌面双栏变为“原文/整理稿”切换；编辑工具条收纳，主按钮固定可达。支持390px、768px和桌面1440px，以及浏览器200%缩放、Safari中文输入、键盘和触摸操作。

## 5. 知识库与可追溯内容

### 三层内容，不把笔记当原文

| 层次 | 保存内容 | 后续使用规则 |
|---|---|---|
| 原始资料 | 文件/网页快照、哈希、抓取时间、来源地址、原页预览 | 不被AI摘要覆盖；来源变化建立新版本 |
| 识别证据 | 页面/区域、文字、表格、图片、识别引擎、缺页和校正记录 | 可对照原文件；用于事实引用和核验 |
| 知识笔记 | 摘录、分析、用户思考、AI整理稿、结构化正文、分类 | 可用于对话与创作，但保留摘录/推断/人工撰写的区别 |

首批分类：文件夹单一归属、标签多选、用途多选（教学/政策研究/培训/公众号/演讲等）、处理状态（收件箱/已整理/待复核/已归档）。AI建议标题、摘要、标签和用途；新增文件夹或移动大量笔记先给可撤销结果预览。自动整理保留来源，不能自动赋予“已核验”状态。

默认新资料与笔记为个人可见；用户明确加入共享资料库时说明共享范围。已有共享政策资料保持既有权限，历史私人笔记不因统一检索而公开。权限在检索前过滤，并在阅读图片、续跑任务、导出时再次检查；业务员只能阅读有权访问的政策情报与成果日报。

知识库里的笔记可“继续讨论”“用于创作”“生成配音”。转换时传递ID与修订号，不要求复制正文。引用笔记时，原始证据存在则继续向下追溯；只有AI总结的内容不能伪装为官方依据。

## 6. 创作中心：选资料、说目标、看成品

普通用户路径：选资料/笔记 → 选择目标（例如8页教学PPT）→ 自动生成可编辑初稿 → 预览、局部修改、导出。高级用户可展开中间事实与母稿。

1. 自动读资料，建议标题、受众、主题、结构、格式和篇幅；保留用户已明确填写的值。
2. 根据材料生成内容模板的实际字段：教学任务填“学习目标、重点、例题、练习、评价”；政策任务填“适用对象、变化、时间、条件、行动建议”。不能要求教学资料先填写中考地区、年度等无关必填项。
3. “从资料提取内容结构”与“从模板库选择排版样式”分开。资料没有现成模板时，系统可以建议教学结构，并标明为生成建议；不要把建议说成原文内容。
4. 共用执行链：资料检查→候选事实/素材块→内容母稿→格式变体→来源预审→渲染/导出。当前已有自动链负责事实和母稿，改造其输入与统一状态，不重写相同能力。
5. 用来源标记、缺失字段和冲突提醒代替大面积空白表单。只有影响结果的关键缺口才询问；其他采用可见默认值。
6. 用户明确要整套草稿时自动完成内部步骤；外部发布、共享范围扩大和超出既定费用预算另作明确操作。来源预审不替代人工事实确认。
7. 可局部重做某一页PPT/某段文章/某个视频场景；未修改部分及引用、人工锁定文字保留。资料更新只标记受影响内容，不能自动替换已交付版本。

### HCS、GIF Factory 与多格式输出的分工

内容与证据先统一，视觉母版再共用。HCS负责网页布局与视觉方案；可编辑PPT由现有结构化幻灯片导出器生成；GIF Factory负责动态图卡；视频沿用场景、字幕、配音与FFmpeg链。各格式记录能力限制，不声称任意HTML能无损转成可编辑PPT。

正文、DOCX/PDF、网页、PPT、GIF、WAV/MP3能力、带配音MP4分别显示真实输出状态。已生成网页与视频母版但尚无MP4时应显示“待渲染”，不能在任务成功摘要中暗示全部交付。新增音频格式先由现有音频转换器能力检测决定，首批沿用WAV。

## 7. 公众号编辑器与定时任务

公众号首期覆盖：正文富文本、封面/摘要、插图、标题层级、引用样式、字号间距、手机预览、一键复制富文本、HTML导出。与知识库/创作稿共用文档模型；提供内联样式的公众号导出变体，不能直接把普通网页CSS等同公众号格式。

图片复制兼容、上传域名与公众号草稿接口需单独适配。第二期再接入用户自己的公众号授权、图片上传与草稿保存；记录失败状态并允许重试，发布仍是明确操作。本地安装包不能依赖开发者当前会话中的连接器凭据。可复用以前项目的方法，但应先找到代码、确认依赖和复用边界，不能将“曾做过”写成“已集成”。

自动任务共用任务引擎与知识库：配置来源、关键词、时间窗、去重规则、日报模板、接收/输出位置；显示来源成功率、覆盖时段、缺失来源及完成时间。采集失败不能生成看似完整的日报。通知通道与自动发布使用明确配置和权限，不默认对外发送。

## 9. 验收与风险边界

每项只做必要的定向验证；修复导致的新失败才扩大范围。不能仅靠mock结果或接口200宣称真实文档识别正确。

| 验收场景 | 必须满足的结果 |
|---|---|
| 任务管家：Flash/Pro，思考关/开；指定材料/不指定/无匹配 | 兼容请求；资料不足为可继续状态；不选无关资料；保留步骤结果 |
| 原教学PDF与截图问题 | 原文件预览正确；按页核对关键标题、数字、图表；无无人机等无来源内容混入；不能复现时明确记录 |
| 同名不同文件与快速切换任务 | 上传预览、任务、file_id和结果属于同一内容哈希；旧响应不能覆盖新结果 |
| 公众号文字/长图/图表/验证页 | 能获取的准确保留正文和图；受限页明确说明并给可用导入方式；不存验证提示为正文 |
| 文本+图表PDF、扫描PDF、隐藏文本层错误PDF | 同时识别可见文字与关键图表；页面对应；不拿错误文本层当唯一证据 |
| 超30页、超50MB、单页大图、某页截断 | 不要求人工拆分；受工作台配额约束时明确解释；成功页续跑不重复识别；页序完整 |
| 笔记阅读与编辑 | 默认排版；中文输入正常；表格/引用/图片与旧Markdown无损往返；版本冲突不覆盖 |
| 教学材料→PPT/讲义/公众号/视频 | 自动填提纲与正文；PPT文字可编辑；视频实际含配音；所有重要事实可回原文 |
| 三角色与两主题、桌面/手机 | 业务员不能调用创作/私有资料；创作者不能越权；格式项不重叠，不产生横向滚动 |
| Windows/Mac升级 | 账号、原数据、密钥可用；新增表迁移可恢复；原生Mac本机验证单列，不能用Windows替代 |

需要收集的最小复现材料：失败公众号URL、出现错文的PDF原文件（通过工作台导出其资产，不传密钥）、任务ID、当时模型/思考设置、脱敏错误详情。它们用于最终根因与回归，不阻碍方案实施准备。学生资料未经授权不放入公开安装包或测试仓库。
