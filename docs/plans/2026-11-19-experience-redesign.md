# EcuStudio 全面体验整改方案

日期：2026-11-19  
依据：本轮用户逐项反馈；源码审计基线 `7834f5d`，包版本 `0.10.0`。  
状态：**产品设计与实施方案，尚未实施到运行版本。** 配套工程文件：[实施、审计与验收计划](2026-11-19-experience-implementation.md)。

## 1. 本轮决定：围绕普通职员重新组织整套工作台

本轮覆盖首页、资料、编辑器、知识库、Agent 对话、内容创作、项目、成果管理和跨端体验。完成标准是用户能自然地完成“放入材料 → 理解整理 → 做出作品 → 继续修改”，而不是单个按钮存在、接口返回成功。

直接采用用户提出的产品要求：

- **笔记本统一改为知识库，团队原文统一改为原始资料。** 导航、按钮、面包屑、空状态、搜索、通知、帮助与无障碍名称全部同步。旧链接继续可用。
- **所有正文编辑器统一所见即所得；格式工具使用图标。** 不再要求先编辑 Markdown 再点击预览才能看见排版。源码作为用户主动选择的高级入口保留。
- **首页提供真正的 3D 动效与有用的动态信息卡片。** 书院仍为默认主题，曜石保留，两套主题均执行新的交互设计。
- **知识库和成果库使用一致的列表、卡片、筛选、分类与批量操作。** 对话也有持久分类和搜索。
- **AI 创作对话成为完整 Agent 工作区。** 接资料、找资料、整理、撰写、制作为一条连续路径；原对话能看到过程、预览、下载并继续改版。
- **HTML 制作和 HTML 转视频成为明确的一等入口。** 已有能力接入统一流程，不再藏在项目内部。
- **项目默认只保留“资料、写稿、作品”三项主体。** 专业参数放到具体功能的可展开设置中；正文连续编辑，改动后能知道哪些作品需要更新。

减少重复表单、重复选择、来回跳页和没有解释的专业字段。必要的说明紧邻操作；导出和保存等业务动作使用清楚的中文，编辑格式工具则使用图标、悬停说明和键盘提示。用户不必猜图标，也不必学习 Markdown。

## 2. 当前事实：哪些缺失，哪些已有但没有组织好

以下为本次代码核查；服务测试和外部实测的边界见配套工程文件。

| 用户体验问题 | 当前实现证据 | 整改性质 |
| --- | --- | --- |
| 原始资料显示 Markdown 字符 | `web/main.tsx` 的 Snapshot 正文直接输出 `p.text`，版本对照使用 `pre` | 修复阅读器，同时保留段落与页码引用 |
| 编辑器有文字按钮、切模式才能阅读 | `DocumentEditor` 的 `iconToolbar` 默认 false；`DocumentReader` 由不同调用参数决定工具栏和模式 | 建立统一编辑规范，替换所有正文入口 |
| 特定内容退回整篇源码 | `DocumentReader` 对 HTML、公式、脚注触发 `preserveSource` | 新增保真内容块，避免整篇退回代码 |
| 导入过程不清楚 | `InputForm` 主要轮询任务并显示最后一条消息；另有跳转“查看进度与重试” | 同页持久进度、真实阶段、成功去向 |
| 知识库缺少统一管理体验 | `NoteGallery` 主要是瀑布卡片；批量操作在另一块 `KnowledgeBatch` 中 | 共用选择状态，补齐视图、目录、标签和筛选 |
| 对话历史不易找、难分类 | 数据已保存到 SQLite；页面有历史列表，但无文件夹；列表只取最多 200 条 | 保留原历史，增加分类、分页搜索、恢复定位 |
| 上下文查找弱、长期对话能力有限 | 当前笔记选择最多 8 条、合计 4 万字符；模型历史只取最近 10 条 | 按模型容量管理上下文，历史摘要与检索协同 |
| 等待回答缺少实时感 | 两条模型请求路径都是 `stream:false`；已有任务轮询和用量统计 | 统一流式适配器、事件恢复、可读执行状态 |
| 回答操作不完整 | 普通回答主要显示配音和保存笔记；其他产物功能散布于附件组件 | 统一回答与成果操作栏 |
| HTML、视频能力藏得深 | 已有 `html-film`、`project-html-films`、`chat-adaptations` 等模块 | 直接复用并统一进入、预览和改稿路径 |
| 项目页复杂 | 多个独立制作组件和操作区堆叠，正文按 blocks 分别编辑 | 重排页面，建立连续正文与作品版本关系 |
| 成果管理与笔记管理不一致 | `ArtifactLibrary` 已有筛选和批量打包，但独立实现 | 共用管理框架，保留文件特有预览与版本能力 |

因此，本轮同时包含缺陷修复、结构重做、现有能力整合和新能力建设。已有的权限、原件、引用、历史版本、任务恢复与导出能力继续作为基础。

## 3. 全局导航和完整路径

| 一级入口 | 用户在这里做什么 | 二级入口 |
| --- | --- | --- |
| 工作台 | 开始今天的工作、继续未完成事项 | 一句话开始、最近工作、处理中的任务、今日更新 |
| 资料库 | 收集并阅读未经改写的资料 | 原始资料、导入资料、识别与转写、资料更新、订阅与日报 |
| 知识库 | 整理可复用的知识、笔记和摘要 | 全部、文件夹、标签、最近编辑、收藏、回收站 |
| AI 创作对话 | 带资料讨论、检索、执行制作任务 | 新对话、最近对话、对话文件夹、全部搜索 |
| 内容创作 | 按想得到的作品选择制作方式 | 文档、PPT、网页、公众号、音频、视频、动图 |
| 项目 | 持续完成同一主题的一套作品 | 资料、写稿、作品 |
| 成果库 | 找到、预览、下载和继续修改成品 | 全部、文件夹、标签、格式、来源项目、历史版本 |

任务中心作为全局任务入口常驻；设置、账号管理放在侧栏下部。业务员只看到有权限使用的资料、日报和成果，服务端同时校验。搜索结果、文件夹数量也必须服从访问权限。

“资料库”表达原件与出处，“知识库”表达用户整理后的知识，“成果库”表达生成并保存的作品；这三个名称不隐含分享范围。每个内容旁明确显示“仅自己”或“团队可见”。

核心流程：

```text
网址 / 文档 / 图片 / 录音 / 粘贴文字
                  ↓
     原始资料 + 读取进度 + 来源预览
                  ↓
       知识库：整理、分类、编辑
                  ↓
      多选材料 → AI 对话 / 开始创作
                  ↓
         草稿 → 预览 → 保存作品
                  ↓
       成果库 / 项目 → 继续修改

任意一步都能回到来源；刷新、切换页面后能接着做。
```

简单创作无需先建项目；同一主题需要多份作品时，用户可将当前对话与成果归入项目，复用已输入信息。

## 4. 工作台：有 3D 感、有行动能力的登录首页

### 4.1 首屏结构

首屏主区域为“一句话开始”：例如“把上周三份教学资料做成 10 页培训 PPT”，下方支持直接拖文件、添加知识库内容、选择作品类型。点击示例填入需求，用户直接编辑或提交，不进入第二套表单。

右侧为可互动的 **3D 创作台**：资料、知识、作品三组实体卡片依次展开，使用景深、光照、轻微视差和层次变化。鼠标移动产生轻微倾斜，点击对应区域进入真实功能；触屏点击即可操作。视觉上表达材料被整理成作品，而不是无意义装饰。

下方显示四类真实信息卡：

1. **继续上次工作**：最近对话、未完成草稿、正在制作的作品；主按钮直接回到上次位置。
2. **正在处理**：当前任务阶段、页数或处理数量、取消和恢复；完成时卡片转成可打开的成果。
3. **需要你看一下**：识别不清晰、来源更新、需要校对、草稿未保存等可处理事项。
4. **今天的新内容**：新导入资料、可见日报、新完成成果；每张卡片都有明确去向。

### 4.2 动效清单

| 场景 | 动效与反馈 | 目的 |
| --- | --- | --- |
| 首次进入 | 3D 场景展开，卡片错峰进入 | 建立空间层次，突出可行动内容 |
| 卡片指向/点击 | 透视倾斜、轻抬升、边缘光、按压回弹 | 告诉用户它可以点击 |
| 文件拖入 | 落点区域高亮，文件缩略图归入材料卡 | 明确接收成功及去向 |
| AI 处理中 | 状态点脉动，当前步骤展开 | 显示真实工作状态 |
| 任务完成 | 进度卡变成成果卡，轻微完成反馈 | 不让成功只停留在短暂提示条 |
| 页面切换 | 短距离位移与淡入，保持主要内容锚点 | 保持连续感 |

实现采用延迟加载的 WebGL 3D 场景与 CSS 透视卡片。WebGL 初始化失败时使用立体静态/CSS 版本，仍能完成所有操作。切后台停止渲染；手机降低粒子与反射复杂度。尊重系统减少动态效果设置，同时保留状态文字。书院以纸张、柔光、木色和绿色层次呈现，曜石以深色玻璃、边缘光和空间层次呈现。

**性能验收目标**：常用桌面设备交互动效目标 60fps；测试手机目标稳定 30fps 以上；首页业务内容与输入框不等待 3D 初始化。以实际设备测量为准，禁止用空场景截图宣称性能达标。

### 4.3 引导方式

首次使用显示三项可完成动作：导入一份资料、整理成知识、生成第一份作品。完成后自动收起，支持跳过和重新查看。引导出现在真实操作旁，不增加强制介绍页。老用户优先显示继续工作，不反复展示新手流程。

## 5. 统一编辑体验：直接看到排版，直接修改

### 5.1 全部适用入口

文字导入、知识库正文、识别结果校对、AI 回答转编辑、项目基础稿、公众号正文、配音文字、网页及视频中的可编辑文案，都使用同一套编辑内核、工具栏、快捷键、保存反馈和内容转换规则。

原始资料默认是可读的只读正文，并保留原文件。用户选择“整理到知识库”才创建可编辑副本，避免编辑行为悄悄改变证据原件。

### 5.2 工具栏和编辑行为

- 格式操作使用统一图标：标题层级、加粗、斜体、下划线、删除线、高亮、链接、列表、引用、表格、图片、撤销/重做。工具按常用程度分组，小屏折叠为图标菜单。
- 图标有悬停说明、键盘焦点说明、`aria-label` 和快捷键提示；选中文字时显示同一套浮动工具。桌面点击区域不少于 36px，触屏不少于 44px。
- 输入、粘贴 Markdown 后直接形成排版；粘贴 Word/网页保留合理段落、表格、链接和图片，去除无意义格式。中文输入法组合输入不被自动格式化打断。
- 表格支持增删行列、拖动列宽、粘贴表格；图片支持插入、替换、说明、尺寸调整；来源引用可点击回到原始资料。
- 高级 Markdown 源码可按需打开。公式、脚注、嵌入内容使用可识别的内容块；不支持的部分保留原片段并标记，不能因为一个片段让整篇变成源码，也不能保存时静默丢失。
- 支持自动保存、明确的“正在保存 / 已保存 / 保存失败”、版本恢复与并发冲突提示。离线或提交失败保留本地草稿，恢复时对照服务端版本，不能覆盖其他设备的新稿。
- 选中文字可执行“改写、缩短、扩写、纠错、整理为表格”等操作；先展示局部修改对照，再接受或撤销。整篇 AI 重写也保留旧版。

**阅读与编辑是一套排版。** 有编辑权的知识稿直接编辑，无需“编辑 → 阅读 → 预览”的重复往返。导出预览仍保留，因为纸张分页、公众号手机布局与视频时长属于不同成品效果。

## 6. 资料库：导入看得见、结果看得懂

### 6.1 原始资料

正文默认渲染标题、列表、表格、图片、引用、链接和公式。顶部放标题、来源、导入时间、可见范围与原文件入口。正文侧边可展开原网页/PDF 页面对照，段落和页码引用保持可定位。

主操作为“整理到知识库”“带入 AI 对话”“开始创作”。版本更新默认展示可读差异，删除、增加和改动数字有明确标记；原文代码只在高级查看中出现。

### 6.2 导入资料

一个统一导入框支持网址、文件、粘贴文字和拖放。识别类型后呈现必要选项；标题自动建议，可直接修改。保存位置和可见范围明确且有合理默认值，团队共享必须由有权用户选择。

网址导入在原页面展开进度卡：

```text
正在读取《你输入的标题》                        取消
✓ 已连接网页
● 正在提取正文与图片                  已处理 3 / 8 张图片
○ 正在整理内容
○ 保存原始资料
已用时 18 秒 · 最近收到进度：2 秒前

完成后：已保存到「原始资料」
[打开原始资料]  [整理到知识库]  [用这份资料创作]
```

阶段是任务实际事件，不播放虚构的步骤。上传字节、页数和图片数量可给确定进度；未知长度的网页读取使用循环动画与阶段说明，不编造百分比。超过合理等待时间显示仍在等待的位置，并提供取消或恢复。

任务刷新后恢复、离开页面后进入全局任务入口；重复点击不创建重复资料。局部图片失败时显示“正文已保存，2 张图片未识别”，可重试失败项，不冒充完整导入成功。

公众号等受限网页失败时，说明“网页要求验证，工作台暂时无法直接读取”，给出粘贴正文、上传 PDF/图片、打开原网页三条实际可行路径，保留已经填写的标题与网址。

### 6.3 识别与转写：按审核清单整改

页面用“文件变文字、图片识别、录音转文字”三个直观入口，解释输入和产物。上传后自动探测文件类型，不让用户选择模型协议或分页技术。

- PDF 逐页统计：可提取文本、扫描图片、混排图表、空白页分别处理；大文件按页与服务上限自动分组。
- 保留原文件哈希、页码、位置、处理方式和识别覆盖。图表的数字、单位、表头关联原图；无法确认的内容标为待核对，不能按文件名编造正文。
- 校对页面采用原件与可编辑正文对照；点击识别段落定位原页。显示“已识别 X/Y 页、待核对 N 处”，不把任务成功等同内容准确。
- 音频切段由系统完成，显示处理时段，失败段单独重试；保留时间定位，不凭空承诺说话人识别。
- 完成操作统一为“保存到知识库、带入对话、开始创作、下载文字”；输入与来源随结果传递。

### 6.4 资料更新：从变化到修改建议

“更新与影响”改为“资料更新”。卡片先回答“哪份资料变了、主要变了什么、哪些内容引用了它”。展开后提供原文新旧对照、关联知识、项目和成果，以及具体引用位置。

用户可将关联内容标记待复核、让 AI 生成修改建议、逐项接受修改。旧作品仍保留，标注依据版本；未经选择不覆盖用户已编辑的正文和成品。权限不足的关联内容不出现在列表或数量中。

### 6.5 订阅与日报：知道何时运行、覆盖了什么

页面显著显示开关、下一次时间、上次结果、来源数量，并提供“现在检查一次”。规则用“关注什么 / 从哪里找 / 什么时候整理”表达，复杂参数默认收起。

日报必须区分：发现新内容、已检查但没有新内容、部分来源失败、全部失败、尚未执行。来源覆盖列出成功/失败/未执行，失败能单独重试。显示时区与本机服务运行要求；电脑关机期间不能宣称按时监测。

日报摘要可保存知识、进入对话或制作文档。信息抓取和自动生成日报以真实订阅设置为准，不暗示所有资料默认自动抓取。重复定时触发、手动触发和恢复补跑要去重。

## 7. 知识库：能整理、能寻找、能批量使用

### 7.1 页面布局

```text
知识库                          搜索知识             + 新建
┌ 分类侧栏，可折叠 ┐  全部 / 最近 / 收藏   筛选   列表 ▤  卡片 ▦
│ 全部知识    128  │  已选 5 条：带入对话  开始创作  移动  标签  更多
│ 培训资料     26  │  ┌标题 / 摘要 / 文件夹 / 标签 / 来源 / 更新时间┐
│  ├教师培训   18  │  │ 勾选内容，原位查看和编辑                    │
│  └家长课堂    8  │  └──────────────────────────────────────────┘
│ 标签             │
│ #教学        32  │
│ #招生        14  │
└─────────────────┘
```

数量为布局示意，不代表当前用户数据。

### 7.2 管理能力

- 列表/卡片视图、排序、侧栏展开状态、列宽按用户保存；手机分类侧栏变为抽屉，批量工具固定在底部。
- 文件夹支持层级、新建、重命名、拖动移动和数量；默认计入其子目录，说明统计规则。删除文件夹默认将内容移至未分类，不连带删除知识。
- 标签支持多选筛选、搜索、计数、重命名和合并；重命名影响范围明确。计数只统计可见、未删除内容。
- 搜索覆盖标题、正文、标签和来源，支持日期、文件夹、用途、状态、拥有者/共享范围筛选；采用服务端分页，不能只搜索当前加载的卡片。
- 批量选择与当前筛选共用一个列表；支持选当前页、选所有匹配结果、跨页选择并显示数量。批量操作支持移动、加标签、移除标签、收藏、归档、删除及恢复。
- 批量加标签不得覆盖原有其他标签。删除进入回收站，关键批量变更可撤销；误操作不靠重新导入恢复。
- 每条知识显示来源、更新状态、最后编辑时间；打开后正文统一编辑，分类信息放侧栏，减少表单占位。

### 7.3 多选进入对话

选中多份知识 → 点击“带入 AI 对话” → 选择当前对话或新对话 → 在输入框上方看到可移除的上下文卡片。原有标题、用途、来源和版本一并传递，不要求再复制正文。

大批量材料采用检索式引用：系统说明哪些资料全文带入、哪些按需检索，以及估算占用。不能把“选择了”显示成“全部全文读完”。超限时优先给出自动摘要/分批处理方案，保留完整引用链。

## 8. Agent 对话：持续工作、可观察过程、直接交付

### 8.1 三个区域

- **左侧：对话管理。** 主导航下可快速打开最近对话，完整对话页支持文件夹、收藏/置顶、重命名、归档、移动、搜索标题和消息正文；刷新、重新登录后仍在。文件夹属于具体用户。
- **中间：对话与输入。** 展示可读回答、引用、执行步骤和产物卡；输入草稿自动恢复，不因切换对话丢失。
- **右侧：本次工作。** 可折叠显示已选材料、任务计划、正在制作的作品和预览。手机使用页内抽屉，输入框始终可操作。

回到旧对话时恢复消息、上下文、任务、附件版本、草稿与阅读位置。持久化不等于把所有历史塞给模型：服务端保留完整记录，再按容量使用近期消息、可追溯摘要和检索，解决目前仅取最近 10 条的限制。

### 8.2 输入框上方的工具区

统一图标排列：添加文件、添加知识、添加原始资料、添加网址、工具与技能、作品类型。笔记选择器提供独立搜索、最近使用、文件夹、标签、多选及选中数量，不再只列最近笔记。

检索模式使用“我的资料 / 联网查找 / 一起查找”等容易理解的选项。专业模型和思考设置仍可展开，但不占据日常主要位置。

“工具与技能”集中展示现有能力：提示词优化、文件识别、资料检索、来源核对、写作整理、HTML Creator Studio、GIF Factory、PPT/文档导出、文字配音、视频制作、公众号排版。每项注明“能做什么、需要什么、会得到什么”。

Agent 使用统一能力登记表调用现有模块，遵守账号权限、任务幂等、来源引用与网络/资源边界。用户说“把这些知识做成网页并配音转视频”，系统能在同一对话给出计划、制作网页、展示预览、继续配音渲染，并回传成果。

普通生成任务按用户指令连续执行；信息缺失能从材料推断时给出可修改默认值，只有影响结果的关键缺口才问。用户未选择自动制作时，可在网页预览处调整后再生成视频。涉及共享私人内容或向公众号写入时，在最终动作位置说明目标与内容，沿用已有授权，不反复确认已授权步骤。

### 8.3 等待反馈与流式输出

发送后立即出现明确反馈：排队、读取材料、搜索、整理答案、生成文件等实际步骤。步骤可展开看来源和工具结果，默认不暴露内部协议、参数 JSON 或模型私密推理。

文本支持边生成边显示；工具调用参数片段不作为正文显示，工具结果回来后继续输出。提供停止、重试失败步骤、继续生成；已生成文字和已完成作品保留。

刷新/断线通过事件序号恢复，不重复发起同一模型请求或生成相同附件；流式中途失败标明“尚未完成”。DeepSeek 官方 Chat Completions 支持流式和用量返回；需按实际选用端点适配，不能把 Chat Completions 与 Responses 的事件协议混用。[官方 Chat Completions 文档](https://api-docs.deepseek.com/api/create-chat-completion/)、[Responses 文档](https://api-docs.deepseek.com/guides/responses_api/)

### 8.4 用量与上下文状态

输入区附近显示“已选 X 份材料”“本轮上下文预计使用约 X%”，展开可看知识、附件、历史和输出预留。使用实际模型能力，不能把字符数当 token，也不能固定写一个适用于所有模型的上下文上限。

完成后显示本次输入、输出、缓存命中等接口实际返回值；未提供的字段显示未提供。若展示费用，明确计价版本与估算属性。对普通用户默认精简为占用条与本次用量，详细统计折叠。

达到容量阈值时自动准备摘要或检索模式，说明会使用的材料和保留的来源；完整对话始终可追溯。切换模型重新计算预算。

### 8.5 回答与成果的完整操作

统一高度、间距和图标，按当前回答类型显示可执行功能：

| 操作组 | 可用动作 |
| --- | --- |
| 整理与复用 | 复制、编辑、保存到知识库、加入项目、继续追问 |
| 文档与展示 | 生成 Word、PDF、PPT、网页 |
| 媒体制作 | 生成配音、GIF、视频、网页转视频 |
| 发布准备 | 公众号排版、手机预览、保存远端草稿（账号可用时） |
| 版本管理 | 修改这份作品、查看旧版、下载、定位来源 |

常用操作直接展示，完整动作放在统一的“制作成…”菜单，窄屏也能触达。没有 HTML、未连接语音、没有权限等情况给出具体条件或引导，不能出现点击后才报通用错误的按钮。选择动作自动携带本条回答和材料，不复制粘贴，不重新填写同一需求。

## 9. 内容创作：按最终想要的东西来命名

| 当前名称/位置 | 新入口 | 用户看到的说明 |
| --- | --- | --- |
| 政策研究 | 资料解读 | 把资料整理成重点、变化和行动建议 |
| 真人口播 | 视频口播稿 | 生成适合直接讲出来的文稿 |
| 写公众号文章 | 公众号文章 | 写稿、排版、手机预览、保存草稿 |
| 讲座 PPT | 演示文稿（PPT） | 生成可编辑幻灯片，支持继续修改 |
| 视频分镜 | 视频脚本 | 整理每一段画面、旁白和时长 |
| 分散的 HTML 入口 | 网页与互动页面 | 制作可打开、可交互、可继续修改的 HTML |
| 项目内 HTML 视频入口 | 网页转视频 | 保留网页动效，添加旁白并导出视频 |
| 分散导出功能 | Word / PDF 文档 | 形成可编辑文档或排版后的 PDF |
| 文字配音 | 配音与音频 | 把正文转为可试听、下载的音频 |

首页卡片按照文档、展示、网页、音视频分组，每个入口带作品示意、输入要求与一个常见示例。用户选知识、拖文件或写一句要求即可开始；默认模板根据目标与材料自动匹配，用户仍可修改。

HTML、PPT、GIF、视频共享内容与资产，但各保留自己的编辑模型：PPT 必须是可编辑元素，不能用整页截图伪装；网页转视频保留原网页动作，不强行经过 PPT；GIF Factory 为需要逐帧与动图制作的任务服务，避免与 HTML 工具形成重复工作流。

## 10. 项目：资料、写稿、作品

### 10.1 默认结构

项目顶部只显示名称、简短目标、当前进度和一个主要行动按钮；“下一步”由项目状态决定。下面三项主体：

1. **资料**：本项目引用的原始资料、知识和对话，标记新增/更新/待核对；一次选入，后续复用。
2. **写稿**：一份连续可编辑的基础稿；说明“其他作品可以依据这份正文生成”。目录自动形成，来源和事实核对在可展开侧栏。
3. **作品**：网页、PPT、文章、音频、视频等卡片，直接预览、修改、下载、生成新版本；已有作品放在首位。

内部仍可保留结构块用于引用和衍生制作，但不要求用户理解每个 block。各类成品需要专门编辑时，在作品旁打开对应编辑器，返回仍回当前项目位置。

### 10.2 字段解释与改动影响

| 用户可见字段 | 默认值/说明 | 对作品的影响 |
| --- | --- | --- |
| 写给谁看 | 从要求提取；未说明用一般读者，可修改 | 用词、解释深度、案例选择 |
| 希望读者知道/做到什么 | 从资料与需求提出建议 | 重点和结尾行动 |
| 正文 | 基础稿连续编辑，自动保存 | 新生成作品的内容依据 |
| 标题 | AI 建议，可直接修改 | 文章、封面、文件命名 |
| 长短 | 简短 / 标准 / 详细；按成品补充页数/时长 | 文档篇幅、PPT 页数或视频长度 |
| 风格 | 少量可视化样例，默认匹配 | 排版、色彩、语气 |
| 朗读声音 | 可试听，沿用用户最近选择 | 音频与视频旁白 |
| 画面比例 | 横屏 / 竖屏；示意图可选 | 网页录制和视频画幅 |

只展示与当前作品有关的字段，不同时展示所有参数。说明位于字段旁；修改正文后提示“3 份作品可更新”，用户选择需要更新的作品。旧版继续可下载，不自动覆盖用户已单独改过的 PPT、HTML 或文章。系统展示新旧差异并说明哪些设置被继承。

失败的渲染、缺少语音连接、来源待核实等问题在对应作品卡内解决，不让整个项目进入一张报错页面。

## 11. 成果库：采用知识库的管理方式

复用可折叠分类侧栏、文件夹和标签计数、列表/卡片切换、搜索、筛选、多选与批量工具。筛选增加格式、项目、生成时间、来源对话、版本和可见范围。

卡片提供真实缩略图和“打开预览 / 下载 / 继续修改”；列表显示格式、大小、版本、来源、更新时间。PDF/DOCX/PPT 有分页预览，网页可交互预览，音视频可播放，GIF 可播放或暂停。不可预览时说明并提供下载，不能假装支持。

批量支持下载打包、移动、加/移除标签、归档、删除与恢复。更改显示名称不篡改旧文件或引用。删除某次生成版本时说明影响，仍被其他内容引用的文件不能直接物理清除。

作品可加入知识库继续整理：文档提取正文，音视频按用户选择转写，保留作品链接和来源。不能仅把一个下载路径保存成“知识”就算完成互通。

## 12. 普通用户需要的说明与恢复能力

每个页面都提供简短、可以折叠的“这里可以做什么”；空页面有示例和主按钮，成功后有结果及下一步，失败后有可执行解决方法。说明与动作同页，不依靠长手册补救不清楚的产品。

| 状态 | 应呈现的内容 |
| --- | --- |
| 没有资料 | 告诉用户支持什么，提供导入或示例 |
| 正在处理 | 动画、当前阶段、真实进度、已用时、取消/离开说明 |
| 部分成功 | 哪些成功、哪些缺失、能否继续、重试失败部分 |
| 全部失败 | 简明原因、已保留内容、重试/替代输入入口 |
| 完成 | 结果预览、保存去向、下一步操作 |
| 刷新/重连 | 恢复原任务、草稿和当前上下文，不重新扣费创建任务 |
| 没有配置 | 说明缺什么及前往设置的按钮；业务员看到联系管理员 |

用户界面不以任务 ID、HTTP 状态码、token 参数名或内部阶段枚举作为主要解释。技术详情保留在可复制的诊断区，并清除凭据和私有正文。
