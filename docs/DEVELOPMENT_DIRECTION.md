# 开发方向：从一句需求到可交付的作品

EcuStudio 服务于需要备课、研究资料、写稿和做演示的普通使用者。判断一项改动是否值得做，可以用一个问题：用户已经告诉工作台的材料、受众和目标，下一步还要不要再填一遍？

## 当前基线

用户可以在「AI 创作对话」要求老师用的 PPT 和学生用的 Word 活动单，在回答下下载，再用下一条消息改稿。工作台从模型返回的成稿生成本地文件，保存文件与回答的关联。需要精确控制模板、资料共享范围或视觉设计时，可以进入专门的制作工具。源码包含这些能力，已发布安装包的基线仍为 0.10.0。

## 下一阶段的工作包

**2026-11-19 优先级更新：** 用户要求全面整改体验。以 [最新产品方案](plans/2026-11-19-experience-redesign.md) 和 [实施与验收计划](plans/2026-11-19-experience-implementation.md) 为主线：统一所见即所得图标编辑器和任务状态 → 资料/知识/成果管理 → 完整 Agent 工作区与可恢复流式 → 通俗创作与三段式项目 → 3D 首页和全局引导收口 → 双平台升级验收。3D 设计从第一阶段同步开始。全部需求属于本轮总体范围，当前仅方案完成，未实施。

下表保留此前创作质量工作包，它们作为新流程的质量验收内容继续执行，不替代这轮用户指定的体验整改。每包同时覆盖入口、服务端行为、失败恢复及浏览器验收。

| 顺序 | 工作包 | 怎样判断完成 |
| --- | --- | --- |
| 1 | **对话交付的真实质量**。用可公开的合成课程资料，分别要求教师演示、学生活动单，再追问修改其中一份。核对模型实际选择的工具、引用与成稿。 | 两种受众得到不同正文；可编辑 PPT 的分页、Word 的表格与中文、PDF 的阅读顺序经过人工查看；记录真实模型、已执行步骤和失败样例。没有真实账户时先完善夹具和本地文件检查。 |
| 2 | **指定附件改版**。把“刚才的第二份活动单”明确关联到原消息和文件。在原对话展示新旧版，并允许单独下载。 | 一轮交付多个文件后，能准确选择指定附件；修改不会覆盖旧稿或其他附件；刷新后可回到两版的来源；换账号不能读取私有附件。 |
| 3 | **从对话接续复杂制作**。对需要设计确认的 GIF 或配音视频，复用现有视觉任务，将草稿预览、待确认动作和进度带回发起对话。 | 用户无需重填受众、来源与交付格式；核对后才开始渲染；断线或重复点击可找回同一个任务；成果库可以回到发起对话。 |
| 4 | **从成稿走到真实使用**。用 Safari、手机、Office 和有接口权限的公众号分别验收编辑、下载、复制及草稿回读。 | 逐项记录环境、版本和结果；用微信后台核对正文与配图；安装版升级另用隔离的旧安装副本核对账号、原件、笔记、凭据和回滚。 |

对话中生成私人文件可以直接完成。私人笔记转团队素材、消耗额外模型或渲染预算、向外部账号写入草稿时，应在动作发生的位置说明范围和后果。沿用现有账号权限、来源引用、任务检查点及签名更新机制。

第一批已将材料拖入、原消息任务状态与重试、Office 分页预览和指定附件改版接成同一条路径。合成课程已在浏览器完成教师 PPT 与学生 Word 双交付、只改活动单、找回旧版；真实模型验收仍待连接账户。第二批已将公众号手机预览、换主题、草稿回读和逐页配音视频带回原对话。用同一份合成材料走通了第 2 版活动单转家长文章、原教师 PPT 转视频和只改一页旁白。

真实使用验收随本轮对应工作包执行：用同一课例检查真实模型是否按受众改写、是否准确引用材料；在试听中核对语速、停顿、数值读音和每页时长；用 Safari、手机核对排版。维护者明确指定测试公众号后，再核对真实草稿与手机预览的一致性。每项分别记录实际环境、样本和未通过的细节。

当前实现与验收边界见 [工程交接](../HANDOFF.md)。新聊天可使用 [接手提示词](NEXT_AGENT_PROMPT.md)。
