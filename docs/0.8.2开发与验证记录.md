# 0.8.2 Mac 停机修复记录

用户报告从设置更新0.8.1时，旧服务仍运行。原代码忽略launchctl退出状态，仅依据已记录PID及完整入口路径判断服务，没有端口进程发现和工作目录核验。未取得用户Mac原生日志，因此不能将单一启动方式判定为该机器的已确认根因。

修复集中于deployment/upgrade.mjs的stopMacService，供升级器与macos-service.mjs复用。依赖保持为Node内置模块，临时目录中的旧更新执行器复制upgrade.mjs后可以独立运行。进程发现结合lsof监听端口、PID记录、UID、Node命令、工作目录及启动时间；只处理同一安装实例，拒绝另一个启动器持续重启的服务。先SIGTERM；仅维护锁定、已确认无运行任务的升级允许对身份未变且拒绝退出的进程进行有界升级处理。停止结果写入data/logs/mac-stop.json。

服务端preClose显式结束SSE长连接并清理定时器；避免浏览器仍开着任务页面时阻碍退出。更新界面依据database.sqlite实际存在情况区分工作目录与完成的数据备份。Mac启动结果不再硬编码旧版号。

Repair-Upgrade.command由用户在原登录会话运行，使用新包的升级器。旧页面更新仍会复制旧版升级器，因此首次恢复需运行该入口。检测未完成升级锁时先走原恢复机制，不直接删除锁或业务数据。

验证：Mac命令模拟覆盖7个停机与误杀防护场景；真实HTTP SSE长连接打开时关闭服务成功；既有升级与恢复回归测试、TypeScript检查、构建和发布包清单检查。Windows原版页面升级另做隔离验证。Mac原生launchctl、钥匙串和本机安装尚待该电脑实际验证。
