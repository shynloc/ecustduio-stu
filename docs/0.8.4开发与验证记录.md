# 0.8.4 开发与验证记录

日期：2026-11-17。范围：11月17日整改方案第一批可交付修复及知识库、导航、公众号排版入口。

## 改动

1. `model-request`统一判断思考模式与工具选择组合、400分类和网络错误。`workflow-agent`将必需技能作为带版本/哈希的宿主上下文，保留正常工具调用与reasoning历史。
2. `material-search`先检索相关共享资料。无匹配计划状态为needs-material，不能执行为空项目。
3. `document-quality`绑定原件SHA-256、提供PDF页图与原文字层证据，识别结果始终需要对照原件。不得把一致性启发式当作准确性证明。
4. `document-parts`使用pdf-lib拆页，固定切片元数据，保证跨次重试哈希稳定。PDF以流方式接收，200MB/2000页；分片默认10页/20MB，串行执行控制内存，超限/超时递归拆小，单页必要时分区域。429有界退避。部分成功明确记录覆盖率，已有检查点复用。
5. `ingestion-web`保留正文、表格、懒加载图片顺序；识别验证页；受允许时使用DeepSeek读取后备和图片识别。图片识别标待核对，不视为已核实事实。
6. 本机OCR识别含文字、图片及矢量图的混排页，取消原30页上限，增加页面结果缓存。原文层与识别方法区分。
7. Tiptap3.34.0富文本、JSON与Markdown兼容，服务端从JSON生成正文，避免显示正文与供模型读取的正文分叉。旧笔记不强制迁移。新增migration005：note_documents、note_categories、note_history。图片复用资产授权，历史恢复产生新revision。
8. 笔记分类、已保存笔记自动保存、版本冲突保护；原资料更新提示；资料存笔记与笔记反向创作延续原权限和人工核对边界。
9. `creationDefaults`只从当前所选资料带入标题、范围和教学/政策/通用领域。教学缺失信息为待补充，模板正文由既有research/master/content/export链制作；PPT可同时输出DOCX。
10. 输入/处理/输出分组保留旧hash路由。公众号排版导出可离线HTML，脚本清理，图片权限检查，复制富文本；远端草稿和发布不在本轮范围。

## 边界与后续阶段

- 学生原始教学PDF、具体失败公众号URL缺失，尚未复测原案例。需要原件对照才能判断是文件内容、解析、远端返回还是其他原因。
- 没有Mac实机；Mac包的Safari中文输入法、Apple Vision、钥匙串及LaunchAgent升级仍需原生检查。Windows测试不等同Mac验收。
- PDF原件上传不支持浏览器断点续传；分片模型处理支持检查点续跑。单页分区域识别保留交叠内容供校对，不自动删除可能重要的重复表格行。
- 公众号验证或登录限制不能保证自动读取；明确提示恢复入口。
- 后续长期整改继续完成统一逐块证据表、批量移动/撤销、所有入口的统一上下文协议、更完整的成果依赖关系及公众号远端草稿适配。本轮不把这些列为已完成。
