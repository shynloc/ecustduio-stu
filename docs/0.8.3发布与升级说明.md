# EcuStudio 0.8.3：Mac 凭据保存与页面错误修复

本版针对保存DeepSeek密钥时只出现INTERNAL_ERROR的问题，补齐钥匙串异常处理和页面内提示。这个错误不等同于API Key无效：保存阶段只操作本机凭据存储，不调用DeepSeek。

## 学生Mac的处理步骤

1. [下载Mac 0.8.3修复包](https://dshdisk.acks.com.cn/ecustudio/0.8.3/EcuStudio-0.8.3-macOS-UpgradeReady.zip)，完整解压到「下载」等新目录，不覆盖原安装目录。
2. 运行包内 **Repair-Upgrade.command**，使用原Mac登录用户，不使用sudo。脚本沿用原目录并保留账号、资料与钥匙串配置。
3. 回到工作台「设置 → DeepSeek Agent」，先点击 **检查本机凭据存储**。它使用独立临时条目做写入、读取和清理，不读取真实API Key，也不调用DeepSeek。
4. 检查通过后粘贴API Key并保存。成功后开启“允许DeepSeek调用”，再测试连接。

如果提示钥匙串锁定，请在这台Mac打开“钥匙串访问”，解锁“登录”钥匙串；若出现系统授权提示，由本机用户确认。钥匙串密码通常是Mac登录密码，不是DeepSeek API Key；不要把这两个值发给他人。

如果后台服务无法完成系统授权，可在本机运行修复包内的 **Configure-DeepSeek.command**，按终端提示粘贴密钥并回车。输入不会显示；密钥通过标准输入写入同一钥匙串，不进入命令行参数或环境变量。保存和读取校验通过后会重启工作台，以便使用新凭据；请先完成正在运行的任务。

双击脚本无法打开时，可在终端输入 `bash` 加一个空格，把相应.command文件拖入终端后回车。

## 如仍然失败

运行包内 **Check-Keychain.command**，把它输出的检查结果提供给维护人员即可。报告只含存储检查状态、错误码、版本和首页响应状态，不含真实API Key。报告也保存在原安装目录 `data/logs/keychain-check.json`。不要发送密钥、完整data目录或钥匙串文件。

如果当前页面仍能正常进入，0.8.2用户也可从「设置 → 工作台更新」升级到0.8.3；遇到旧服务停不下来的历史版本请用上面的Repair-Upgrade入口。

[Windows 0.8.3安装升级包](https://dshdisk.acks.com.cn/ecustudio/0.8.3/EcuStudio-0.8.3-Windows-x64-UpgradeReady.zip)继续支持设置页一键升级。原有账号、密码、资料、笔记、项目、成果与DeepSeek配置保留。

## 已完成的验证范围

已验证钥匙串进程错误分类、成功诊断文字兼容、写后读取校验、超时和提前关闭输入管道等模拟场景；实际浏览器验证失败留在设置页、输入保留和成功后清空；Windows做真实加密保存和本机存储检查。尚未在学生Mac上执行，不能仅凭这次通用报错确定该机器的最终原因，需以本机检查结果为准。
