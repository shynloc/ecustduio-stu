# EcuStudio 0.8.2：Mac 升级停机修复

发布日期：2026年11月16日。

## 遇到 The old service is still running 的 Mac 用户

此错误发生在替换程序和数据库备份之前。升级没有替换原程序，原账号、资料和配置仍在原安装目录；界面显示的路径可能只是已创建的升级工作目录，不代表数据库备份已完成。

旧升级器只通过LaunchAgent和进程记录寻找服务，不能完整覆盖从终端、相对路径启动、PID记录缺失或失效等情况。0.8.2增加按端口查找，并验证登录用户、Node入口、工作目录和进程启动时间，只停止当前安装实例；正常停机未完成时不会继续覆盖程序。运行中的任务需要先完成。

**这次请运行新版包里的修复升级脚本。只在旧页面反复重试，仍会运行旧版升级器。**

1. [下载Mac 0.8.2安装修复包](https://dshdisk.acks.com.cn/ecustudio/0.8.2/EcuStudio-0.8.2-macOS-UpgradeReady.zip)。
2. 完整解压到「下载」等新文件夹，放在原安装目录之外。
3. 关闭工作台网页，用原Mac登录用户双击 **Repair-Upgrade.command**。不要使用sudo。若Finder不允许运行，在终端输入 `bash `（末尾有空格），把该文件拖进终端后回车。
4. 脚本自动寻找 `~/Library/Application Support/EcuStudio`，其他安装位置会提示输入。若有中断升级，会先恢复；然后停止已核对身份的旧服务、备份、升级并启动0.8.2。
5. 浏览器打开后用原账号登录，设置页确认版本为0.8.2。无需重新创建管理员或录入DeepSeek密钥。

原账号、密码、权限、资料、笔记、项目、成果及DeepSeek配置保留在原目录，Mac钥匙串项目保持不变。不要删除原目录或运行创建空数据库的操作。

如果修复脚本仍提示不能停止，保留终端输出和原安装目录里的 `data/logs/mac-stop.json`，以便针对实际启动方式诊断；该文件只记录停机状态与进程编号，不记录密钥。请不要发整个数据目录或密钥文件。

## 其他用户

[Windows 0.8.2下载](https://dshdisk.acks.com.cn/ecustudio/0.8.2/EcuStudio-0.8.2-Windows-x64-UpgradeReady.zip)

Windows 0.5.0及以上可继续使用「设置 → 工作台更新 → 检查更新 → 一键升级」。Windows手动升级运行新包中的「一键升级.cmd」。Mac新安装运行Install.command；已修复的Mac后续继续使用设置页更新。

修复版包含0.8.1的计划页数、步骤动效和当前内容包修复。新增任务长连接关闭处理、真实停机结果检查以及备份状态提示；未新增数据迁移，也未更换签名公钥或更新源。

Mac停机分支已做命令模拟回归测试，验证失效PID、相对入口、其他用户/目录、进程重用和拒绝退出等情况；任务长连接关闭做了真实HTTP测试。本轮环境仍为Windows，未在这台Mac上执行，不将这些检查表述为Mac实机验收。
