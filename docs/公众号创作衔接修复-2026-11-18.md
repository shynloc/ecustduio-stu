# 公众号创作衔接修复

日期：2026-11-18。基于 0.10.0 继续开发；本次为仓库源码更新，未重新发布已交付安装包或在线更新清单。

## 本次问题与改动

1. 未提交的排版预览此前只在页面内存中，刷新会丢失。现在地址中保留服务端预览引用；刷新后读取原有冻结预览，不重新创建预览或远端草稿。保存后同时保留草稿引用，刷新可直接恢复处理进度。
2. 从排版页去知识库修改正文后，原先无法带着排版设置返回。现在提供“返回公众号排版”，手动保存笔记也保留返回入口。新预览记录区分用户填写的标题、摘要、封面与自动值：修改正文后保留用户选择，自动摘要仍从新正文生成。
3. 返回时若笔记版本已变化，隐藏未发送旧预览的保存按钮，并提示重新生成。已保存记录继续作为历史快照查看，不覆盖微信后台已有内容。服务端已有版本校验和权限检查继续保留。
4. 原“复制图文排版”的纯文本格式只有标题和摘要，降级复制又可能取到 Markdown 源文。现在两种剪贴板格式均来自冻结后的排版正文；富文本包含嵌入配图，纯文本包含完整可读文章。支持 Clipboard API、局域网 HTTP 下的复制事件，以及完整文字降级。实际粘贴时仍需检查目标编辑器对图片的支持。
5. 页面切换后，过期的预览、上传或保存请求不再覆盖当前页面或把用户带回旧页面。

## 涉及模块

- `server/wechat.ts`：在现有预览 JSON 中保留排版选择，无新数据库表或迁移。
- `web/WechatEditor.tsx`：预览/保存引用、刷新恢复、版本变化提示、请求结果隔离。
- `web/workspace.tsx`：正文编辑后返回排版，手动保存保留返回引用。
- `web/compat.ts`：完整文章的富文本/纯文本复制。
- `tests/wechat.e2e.ts`：新增刷新、往返编辑、失效预览和三种复制方式回归。

## 验证

- TypeScript 检查及隔离前端构建。
- 公众号 8 项接口测试：权限、加密、冻结预览、幂等、断网恢复、账号和版本变更。
- 浏览器实际操作：输入 → 知识库 → 排版 → 刷新恢复 → 修改正文 → 返回并重新预览 → 保存草稿 → 刷新恢复回执。
- 书院/曜石、桌面 1440 与手机 390 宽度检查，预览图片实际加载，页面无脚本错误。
- 复制测试通过浏览器替身检查实际发送的完整 HTML/text 数据和回退路径，不代表每一种浏览器的系统剪贴板授权或微信编辑器粘贴效果均已实测。
- 远端保存使用隔离的本地 HTTP 微信接口夹具，不使用真实公众号凭据。真实公众号草稿验收、目标 Mac 钥匙串与旧安装升级仍以 HANDOFF 的待验收项为准。

本机测试使用临时数据库和隔离前端构建，不触及正在运行的正式工作台资料。跨平台结果见仓库 Actions；Mac 接手先同步最新 main，再按 Mac 开发指南启动。
