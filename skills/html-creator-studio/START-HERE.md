# START HERE｜HTML Creator Studio v1.8 Personal Design DNA（开发候选）

> 适用：已安装 **Document to Experience**（或采用同一工作流的 **HTML 创意工坊 / HTML Creator Studio**）Skill 的 ChatGPT、Codex 或其他支持读取附件及创建网页文件的 AI 环境。
>
> **这份文件是给最终用户复制的「任务简报」，不是要替换 Skill 的核心指令。** Skill 规定如何工作；你只要告诉它要做什么。每次使用只需复制以下 **一种** 模板，不必重复粘贴多个模板。

**重要提示**：启动任务卡仅帮助你告诉 AI 这次想做什么；网站展示页本身不会读取你的附件或自动调用 AI，请把复制的文本粘贴到已启用 Skill 的会话中，并附上资料。

**v1.8 全入口共通约定**：AI 在提出视觉方案之前，应参考 Skill 内的 `references/designresources.md`，结合附件而非套模板，提供真正不同的设计方向；事实、数据和引用保留可追溯来源；网页标题、成品文案、旁白、解说与字幕必须先给我审稿，**经我明确批准才能作为正式作品实施**。未批准只能展示明显标注的占位样片。Personal Design DNA 要先真实看到参考，再区分观察/推断/用户确认，未经确认不得写入长期品味。私人参考和简历未经单独授权不外传或公开。



> **先看真的 HTML，再选择。** 默认 Quick 给 2 套可打开的 HTML，Studio 给约 3 套；两者都必须单独审核**完整观众文案和视频口播**。v1.8 可额外建立可复用的个人审美档案，但这是自愿环节，不能阻塞普通一句话创作。

**不知道怎么选？** 不必填技术表单，只需上传附件并复制下方 01 的一句话任务卡。需要研究配色、插画、3D、动效和视频分镜时才用完整任务卡。**视觉选择和文案审核是不同决定**，不能互相代替。

```text

配色、布局、动效强度、是否采用 3D、交互方式等，如果我没有明确要求，请参考 Skill 的设计资源知识库，给出两套实际可看的、构图和设计语言明显不同的 HTML 提案，不要让我先学习技术名词。按照 Skill 的阶段沟通流程进行；一次不要问太多，只询问当前真正需要我决定的事情。确认创意方案后，请先展示最终观众会看到的标题、正文、必要的解说/字幕文案，让我审核；只有我明确确认文案后，才进入正式网页/视频制作。

以附件内容为依据，不要擅自编造数据；交付时请说明如何打开，以及如何通过精准改稿继续修改。
```

**适合**：还不知道自己想要哪种风格、希望 AI 引导完成制作的人。

## 03｜电影级沉浸式：国际创意网站级的视觉体验

> **通用公开预设**：以“电影级空间叙事＋高端科技编辑设计＋真实互动”为艺术方向，不包含任何特定用户的文档或案例信息。章节与内容以本次附件为准。

```text
请调用我已安装的「Document to Experience / HTML 创意工坊」Skill，读取本次上传的附件，为它创作一座电影级沉浸式 HTML 演示网站。

【我的目标】
我想让普通文档变成一件具有专业艺术指导、空间纵深、流畅动画和可操作信息装置的数字作品。第一眼有视觉冲击，深入浏览能真正理解内容。它要像精心设计的国际创意网站，不要像把 PPT 搬进网页，也不要套用常见的渐变卡片模板。

【创意方向：电影级未来研究展馆】
- 风格：Dark Cinematic × Swiss Editorial × Futuristic Data Installation。
- 配色：深蓝黑为基底，电光蓝与冰蓝作为动效和信息强调，少量暖橙点亮关键决策或结论；留白、明暗与对比有严格节奏。
- 排版：超大主题数字或标题、精细等宽编号、非对称网格、留白、细分隔线、HUD 式信息标注。避免密集卡片堆砌。
- 空间：有层次的透视线条、发光路径、粒子与细微噪声；滚动或鼠标能触发轻量空间视差。
- 动效：电影级但克制；文字入场、滚动驱动、时间线展开、图表变化、章节切换要服务叙事。复杂视觉场景之间安排安静阅读段落。
- 3D：请优先评估原生 WebGL / Canvas / CSS 透视能否实现所需空间感；仅在内容确实受益时使用复杂三维模型。不要为了使用 Three.js 而引入 Three.js。

【内容驱动的场景设计】
先理解附件，再将内容重构为若干有清晰目标的章节或“幕”。幕数由内容决定，不强制七幕。每幕都有独立构图、展示重点、交互装置和转场方式。

将适合的内容转为真正能操作的时间轴、比较系统、关系网络、交互图表或流程装置；不能凭空添加原文不存在的数据。如果附件中没有某种关系或数据类型，就不要生造对应图表。

【必须具备的体验】
- 震撼但可读的首屏主视觉，明确的“开始探索”入口。
- 桌面端章节索引、当前章节状态、页面阅读进度和有效的前后跳转。
- 自由浏览模式；如果适合演讲与录屏，再加入全屏逐幕的演示模式和键盘导航。
- 鼠标与滚动相关的视觉反馈，但不妨碍点击、阅读、文字选择和页面导航。
- 手机端完整适配；低性能设备降级，支持减少动态效果偏好。
- 开发版支持精准改稿：定位 DOM、图表、动画以及 Canvas / WebGL 效果，并可生成给 AI 的具体修改要求；正式公开版本默认关闭改稿入口。

【交付标准】
尽量做成可以离线打开的单文件 HTML；如果实现质量、文件体积或稳定性不允许，应明确说明，并交付静态网站与源代码。不要为了单文件形式牺牲运行可靠性。

先按 Skill 的内容分析 → 少量选项共创 → 分镜确认 → 开发 → 测试 → 交付流程进行。已明确的视觉方向不要重复询问；你可以根据附件推荐章节与具体视觉装置。内容删减、事实更改、外部部署仍需我的明确许可。

请现在开始：读取附件，结合 Skill 的设计资源知识库提出网站叙事主线、章节结构，并制作 3 套构图、字体、动效明显不同的真实 HTML 样稿让我选择。设计确定后先给我审观众可见与可听文案，我确认后再正式开发。
```

**适合**：明确想要强视觉冲击、高级动效与精致交互的人。对内容很短、阅读优先或设备受限的资料，AI 应指出必要的性能和可读性取舍。

## 06｜用户还可以用一句话补充要求

在以上任一模板后面加一两句即可，无需重新粘贴 Skill。五种入口只需择一使用，不必叠加：

- **完全交给 AI**：「设计部分你决定，我只确认内容准确性，直接把方案做到能运行。」
- **先看方案**：「先给我三个有明显差异的艺术方向，展示差别后让我选，暂时不要写代码。」
- **限制设备**：「主要用于手机竖屏浏览，动效要精致但不卡顿。」
- **讲座演示**：「我要在投影大屏讲解，确保章节可用键盘逐幕切换，关键文字足够大。」
- **保密内容**：「附件仅用于本地制作，不允许上传第三方服务或公开仓库；对外预览只用脱敏样例。」
- **精准改稿**：「生成开发版时开启可视化改稿；我要能点选目标、预览改动、撤销、复制精确指令，并导出修改结果。请如实说明哪些效果只能通过修改源码实现。」

## 08｜给 Skill 发布者的上架建议（非用户必读）

把这份文件作为 Skill 的入口文档，而不是并入每一次推理的核心长提示词。

推荐在安装页与展示网站配置五个入口：

1. **一键开始**：复制「零门槛」版本，用户只需上传附件。
2. **自定义任务**：展示可编辑任务卡，填写或留空后复制。
3. **电影级效果**：复制完整的高表现力预设，允许之后改配色、动效和 3D 强度。
4. **视频优先 Video Ready**：先确认 HTML 动态设计与逐帧时间轴，再移交视频合成端。
5. **HTML + 视频双用途**：同一套视觉母版，分别交付交互网站与视频构图。

每个按钮旁用一句话说清楚谁适合。默认首先展示「一键开始」，不要一打开网页就让新用户面对十几个专业参数。

本文件已更新为 v1.8 Development Candidate，作为用户任务简报与 Skill 一起分发。HTML 演示、个人审美理解、Remotion 项目与实际渲染均应在相应环境单独验证；候选版不能冒充完成了真实图片、个人档案和视频引擎的公测。

**验收指标**：陌生用户无需掌握“Shader / WebGL / GSAP / 3D”等术语，就能在上传附件后发出有效的第一条消息；AI 能正确识别附件内容、识别已给出的偏好、推荐未知选择，并实际进入创作流程。

## 09｜Remotion 视频优先：最快进入 HTML → 视频工作流

> 已安装 HTML Creator Studio 的用户只需上传附件、复制以下任务卡。不会选的项目保留“请推荐”，AI 分阶段给出可理解的选项。

```text
请使用已安装的 HTML Creator Studio Skill，根据我上传的文档策划并制作一套可进一步编辑的动态 HTML 视觉母版，最终交给 Remotion 生成视频。

【我的目标】
- 目标观众与视频用途：【请推荐】
- 输出：【先 16:9 横版，确认后再做 9:16 竖版 / 两版同时制作】
- 视频时长：【30–45 秒，内容不适合则给我建议】
- 帧率：【30 FPS】
- 视觉方向：【请提出 2–3 套方案供我选择】
- 动效和 3D：【请推荐，优先视频逐帧可重现】
```
