# WORKFLOW MODES｜Quick / Studio 双入口 v1.6

### 目标

降低首次使用门槛，**不降低来源准确性、公开权限、观众文案审批、真实截图与质量门槛**。模式只改变沟通次数、提案数和中间文件形式。

| 流程环节 | Quick（默认） | Studio（复杂/商业/视频） |
|---|---|---|
| 入口 | 上传附件 + 一句话 | 完整 Brief / 视频格式 / 资产约束 |
| 内容理解 | 一屏摘要 + 一次关键确认 | 内容地图、事实来源、数据与未知项 |
| 设计提案 | 2 个可看的页面方向；已授权时可只做一个 | 3 套差异化真实样稿 + 首屏/密集页 + 设计取证 |
| 视觉确认 | 让用户“看样稿选一个”或明确授权 AI 定夺 | Visual Pitch Review + 版式/动画/素材计划 |
| 观众文案 | **完整审稿，必须明确批准** | **完整审稿，必须明确批准**，可能分批审批 |
| 制作 | 最小有效技术栈，不强迫 3D | 按需要 WebGL/Remotion/Hyperframes/音频与双画幅 |
| QA | 首屏 + 核心页桌面/手机截图及基本检查 | 关键场景/动画帧完整截图矩阵，视觉对比、修正记录 |
| 交付 | 直接可用 HTML + 主要文件 + 简洁 QA | Visual Master + Handoff + 关键帧 + 完整报告 |

### 识别用户意图

- 用户说“第一次用、不知道怎么选、快点演示”：默认 Quick；重要选择给专业推荐。
- 用户说“要做成完整品牌作品、商业演示、电影级、视频”：推荐 Studio；如用户指定 Quick 仍需告知画幅/视频工程对流程的影响。
- 用户明示“别问、你决定”：可以自主选艺术方向并出原型，不视作审批文案、可公开部署、允许付费外部 TTS 或允许发布用户附件。
- 用户需求已经充分：不要在 Quick 中硬提一份很长问卷。

### 最少问询

1. 内容与受众（附件信息不足时） → 展示可看的视觉方向、给出推荐；
2. 用户确定视觉方向；
3. 单独交付**完整观众稿**并等待用户批准；
4. 开发并提交视觉截图验收；涉及视频渲染和对外公开，分别再确认权限。

用户不回复文案批准就停在 `copy_pending`，只能继续内部占位技术样片或素材探索，不得生成或交付冒充成品的正式内容。

### 给新用户的反馈模板

> 我读懂附件了，它适合 X。推荐两种方向：A 看起来……，B 看起来……。我已经做出可以查看的两个 HTML 样稿，建议 B，因为……。你选一个或者说“按推荐”。下一步我再把观众会真正看到/听到的完整文案交给你审稿；你不必懂前端技术。
