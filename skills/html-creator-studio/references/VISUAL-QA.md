# Visual QA｜用实际截图验收，而不是 AI 给自己打分（v1.6）

## 三层验收

1. **自动检查**：页面能否加载、浏览器脚本错误、坏图、横向溢出、局部文本裁切、过小字体提示；对比批准的截图基线（如存在）。
2. **设计审查**：首屏是否主题专属、排版是否独特、素材是否有语义、视觉密度/留白是否平衡；可参照 `references/designresources.md` 的内部量表，但评分不代表客观审美。
3. **用户确认**：向用户展示真实样稿截图与可打开 HTML，尊重否定/修改；关键视觉方向获得明确认可后再量产其余内容。设计认可不构成旁白/字幕/事实内容审批。

## 使用自动化脚本

`python scripts/visual_qa.py --cases qa-cases.json --out qa-output/`

参考文件：`templates/VISUAL-QA-CASES.json`；支持相对本配置文件的 `path`，或 HTTP(S)/file `url`。每个 case 参数：

- `id`：稳定编号；
- `path`/`url`：HTML 入口；
- `width` / `height`：本次检查视口；
- `anchor`：可选的 `#section` 跳转，便于真实检查内容密集页；
- `frame`：可选整数；网页需提供 `renderAtFrame(n)`、`setFrame(n)` 或 `__renderAtFrame(n)` 全局接口才能定位（如不可用，报告应标明）；
- `reduce_motion`：默认 true，静止截图便于对照；另设常规动效测试；
- `full_page`、`wait_ms`：可选。

产出 PNG 截图、`visual-qa.json`、`VISUAL-QA.md`。可加 `--baseline-dir <dir>` 比较像素差异，但不同浏览器抗锯齿会有噪声，**像素误差不等于审美评分**。`--strict` 在严重 JS/坏图/溢出时非零退出；文字小或部分裁切可能是启发式 WARN，需要人工确认。

### 重要限制

- `visual_qa.py` 检查普通网页。Remotion 必须用实际 `npx remotion still` 输出关键帧 PNG、`render` 得到视频，再做人工/程序辅助比对；不用浏览器截图冒充 Remotion CLI 验证。
- 不能检测全部元素重叠，也不能充分判断 Shader 粒子是否有意味、中文语义是否准确或素材版权是否完整。
- 视频先检查 scene 开始/中点/结束，涉及复杂运动时多抽样；还要验证 16:9/9:16、字幕安全区、时长/帧率和音画同步。

## 推荐审查矩阵

| 页面 / 画幅 | 具体证据 |
|---|---|
| Desktop 1440×900 | 首屏、一个高信息密度内页、正文阅读与交互状态 |
| Mobile 390×844 | 同样场景；检查触控按钮、中文断行、元素遮挡 |
| 1920×1080 video | 关键帧 0 / 中间 / 结束、旁白字幕同步 |
| 1080×1920 video | 重排后的安全区、字幕空间、上下视觉节奏 |
| Reduced motion | 不运行动态时仍完整表达核心信息 |

若出现“同一套浮卡套三个标题”、没有主题视觉主体、字体不能支撑长中文、关键文字被装饰挤走、使用不明授权素材，优先重做设计而非增加无意义特效。

## 视觉反馈闭环

**设计失误 → 记录具体截图/场景/元素 ID → 归类问题（构图/素材/排版/动效/内容） → 定向改稿 → 重新截图 → 复核差异 → 用户确认**。

最终 QA 报告必须明确：哪些截图已在真实浏览器看过，哪些仍是源代码检查，是否取得用户对视觉方向、观众文案和公开发布的分别批准。
