# 可用性、无障碍与性能验收（v1.7）

## 设备与浏览器

至少在真实浏览器检查桌面 1440×900、手机 390×844 的首屏和信息密集页。根据实际用途增加 320px 窄屏、平板、横屏投影、16:9/9:16 视频画幅。截图和 DOM 指标一起保存，`file://` 受限时必须标记降级加载，不能冒充完整资源路径成功。

## 必做的交互检查

1. 只用键盘 Tab、Shift+Tab、Enter 和 Space 完成主要导航、按钮、下载、模式切换、对话框开关；焦点顺序与视觉顺序一致。所有可点击的功能必须确实工作。
2. 使用语义元素、清晰可见的焦点环、可读的替代文字、标题层级与按钮名称。交互控件原则上不小于 44×44 CSS px；移动端不能依赖 hover 才能操作。
3. 关键正文文本按 WCAG AA 常见阈值检查对比度：普通文字至少 4.5:1，大号文字至少 3:1；不能以“科技感”为由让字幕、轴标签或按钮不可读。
4. `prefers-reduced-motion: reduce` 时禁用非必要的自动循环、视差、闪烁，并保留静态可读内容；持续动效应允许暂停。避免高频闪烁与动画劫持滚动。
5. 所有数据图表同时提供数字/文字说明；仅用颜色区分的信息要增加标签和形状。页面放大到 200% 时关键内容仍可见，不能水平溢出。
6. 检查跳转链接的目标、资源加载错误、浏览器 console/pageerror、图片裁切、触摸操作以及慢设备上的性能退化。

## 质量报告必须区分

- **自动通过**：工具实际测过的结构或具体行为，例如脚本错误、横向溢出、测试用点击动作。
- **人工通过**：有人真实审看并记录的视觉质量、内容准确性、动效节奏、触摸体验。
- **待验证**：客户端没有支持、浏览器无法运行、官方视频 CLI 未执行或第三方服务不可访问。

任何 `PASS` 都要能指向命令、设备/浏览器、输入、截图和日志；不能因为有示例图就推断所有新任务表现良好。
