# Audio Direction｜视频声音设计与观众语言对齐 v1.6

> 本规范只在目标为 `video_ready` 或 `dual`，且用户需要旁白、配音、音乐或音效时加载。无声视频无需强制制作虚构音轨；可交付 silent preview，但必须标注无声。

## 核心规则：口播与镜头共同策划

1. 先确定观看场景（横屏讲解/竖屏刷屏/静音公共场所）、观众、时长和声音形式（真人/TTS/无声）。
2. **先制作观众稿并等待用户明确确认。** 观众不需要知道来源附件存在；避免“原文说、上述文档”制作元话语。事实出处留在工作层/可点开的参考信息，不滥用口播来源提示。
3. 以句群为单位建 `scene_id` ↔ `voice_line_id` ↔ `startFrame,endFrame` ↔ 字幕片段 ↔ 主画面元素的映射。读出时间和画面停留互相约束，不能视频做完再强塞口播。
4. 口播速度采用**试听/估算再校准**而非死规定汉字/秒。技术名词、数字、缩略词需要额外留白，句群之间留自然停顿。
5. 语气/人声类型、背景音乐、音效与声音混音都应由用户选择或采纳推荐；声音资源、TTS 服务使用前须取得所需授权，不上传私密文案到外部 TTS 供应商而不告知。
6. 更改已批准的文案必须重新审稿；仅移动已批准台词的播放时点可按用户确认的时间轴调整，仍需校验字幕匹配。

## 交付数据（可选）

`visual-master/audio-cues.json`：

```json
{
  "version": "1.6",
  "fps": 30,
  "voice_mode": "none",
  "approval": "pending",
  "cues": [
    {
      "scene_id": "scene-01",
      "voice_line_id": "vo-01",
      "copy_revision": "draft",
      "text": "【占位：需经用户批准的解说句群】",
      "start_frame": 0,
      "end_frame": 90,
      "subtitle": "【占位：与已批准口播一致】",
      "visual_target_ids": ["title-01"],
      "music_ducking": "when_voice_present"
    }
  ]
}
```

示例是待审稿占位，不代表任何用户批准或音频合成已经成功。

### 制作流程

- `script approval` → 试听节奏/标记难词 → `timing lock` → 合法配音/音效素材 → 关键帧预览 → 音画实际试听 → MP4 验收。
- 场景时长不足：优先拆分句群/调分镜/增加画面停留；不可擅自删改结论或加速到不可理解。
- 混音在目标平台检查响度、峰值与人声清晰度，保留独立音轨和音量自动化；不要把统一某个 LUFS 值当所有平台强制标准。
- 无配音短视频仍要预留字幕安全区，并在设计阶段验证静音理解。

### 版权与隐私

配乐、音效、人声音色模型、录音、背景素材分别记录创作者、许可、使用范围和是否允许商业发布；未经授权不得克隆真实人物声音。不得向未经批准的外部 TTS/音乐平台传输私密附件或脚本。

## QA

- 已批准文字与 TTS 实际读音一致；数字/单位读法准确；字幕行切在语义停顿处；
- 人声无明显切断、音乐不盖人声，片头/转场停顿符合节奏；
- 无声版本注明 `silent=true`，不要冒充已录旁白；
- 实际对齐检查使用录制音轨/字幕与帧时间轴，不以源码存在推定音画成功。
